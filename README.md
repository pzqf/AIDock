# AIDock

面向多项目、多 AI 工具的开发环境配置管理工具。当前包含 Go CLI、技能盘点、项目技能源管理、经过检查的工具技能文件安装与回退，以及跨副本登记和三方比较。真实 MCP/模型连接和跨副本发布尚未开放。

`E:\work`、`E:\work2`–`E:\work5` 是真实工作目录，只允许授权的只读参考扫描，不能用于写入、同步或恢复测试。开发验证使用仓库夹具和临时目录；正式集成待专用测试项目建立。

需要 Go 1.25+；从本仓库执行：

```powershell
# 直接打开项目工作台；在界面选择独立测试项目目录
go run ./cmd/aidock config --home .artifacts/my-aidock

# 启动独立体验项目：构建程序、首次创建四个示例技能、打开管理页面
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1

# 启动独立五副本体验，不使用真实工作目录
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-replica-demo.ps1

# 本地夹具：不会执行示例技能的脚本
go run ./cmd/aidock skill scan --manifest examples/fixture.scan.yaml --json

# 启动只读盘点界面，自动打开默认浏览器
go run ./cmd/aidock config --manifest examples/fixture.scan.yaml

go test ./...
```

体验数据保存在本仓库 `.artifacts/experience-default/`，只通过真实源计划/事务初始化；再次启动保留你的修改，不重置示例。终端需保持运行，可在页面关闭控制台或按 Ctrl+C 停止。用 `-NoOpen` 仅输出本地 URL，便于在内置浏览器打开；用 `-InstanceName my-test` 建立另一份独立体验项目。初始化中断且未生成完成标记时，脚本拒绝覆盖残留目录，改用新的实例名继续。此启动器不绑定真实工作目录。

关闭编辑工作台会保留当前页面未保存修改，取消保存预览不会写源；刷新页面会丢弃页面草稿。源已启用表示已保存的 Profile 开关，不代表 AI 工具已经加载。AI 工具页面可检查文件状态、验证隔离发现、生成应用预览，并在独立项目预演应用、回退和撤销。预演不初始化 AI 工具、不运行技能代码；经过当前显式检查可安装工具技能文件并回退；副本登记/比较已开放，跨副本候选和独立恢复预演已开放，正式发布仍待实现。

预演使用磁盘上的已保存、已启用完整包。先生成工具预览，再点击「预演本次应用」并确认；完成后可回退、撤销回退或查看最近记录。预演数据和恢复点保存在显式 home 的 `local/native-rehearsals/`，不自动删除；未完成预演必须恢复后才能开始新的预演。CLI 等价入口是 `tool rehearsal run/show/plan/apply/recover`，具体绑定参数见 v0.10 实施记录。

副本预演在「跨副本」页面完成逐项选择后确认，技能与共同基线共用多目录事务。「全部副本预演记录」可重新打开此前的预演，每条记录保留自己的目录范围和回退链。目标父目录失联时历史和恢复计划仍可读取，恢复要等原目录重新可用。CLI 对应 `replica rehearsal run/latest/history/show/plan/apply/recover`，版本 1 记录兼容保留。不要移动/删除本机 home 或恢复标记来绕过未完成事务。

需要生成工具文件时，在跨副本比较结果下勾选 Claude Code/Codex CLI，再预览并确认联合预演。生成和手写占用检查先于任何预演写入；取消保留选择。CLI 使用 `replica generation stage --plan <候选 UUID> --digest <摘要> --tools claude-code,codex-cli`，随后 `replica rehearsal run-generated --plan <生成 UUID> --digest <生成摘要>`。源、生成物和基线一起回退。新的五副本体验实例包含手写技能样例，重复启动保留修改和记录。

生成候选暂存后，关闭预览窗口即可在「发布预检与候选发现」检查逐副本的候选包。默认静态检查；「验证候选工具发现」需明确确认，只在临时项目启动工具。历史预检可重新打开并只读核对有效性。CLI 为 `replica generation check run --plan <生成 UUID> --digest <摘要>`，加 `--probe` 才启动探测；`check show --check <检查 UUID>` 核对有效性，`check history` 列出历史。run/show 证据未完整时返回 `EVIDENCE_INCOMPLETE`/3，候选阻断返回 `STATIC_CHECK_FAILED`/5，过期返回 `CHECK_STALE`/3；JSON 仍包含完整检查结果。历史列表读取成功返回 0。发现通过只覆盖暂存的待生成包，手写项和排除包不在范围内；L3/L4 与正式发布仍未开放。

控制台提供项目/作用域导航、副本筛选、搜索、来源筛选、完整包文件/摘要与分层检查原因。清单中的项目 id 是本次只读选择的临时标识，不是持久注册；不会改写五工作区、运行已有生成器或技能代码。`candidate:` locator 不等于稳定资产 id。

`doctor` 默认只读，证据不足返回退出码 3；静态检查失败返回 5。未实现的跨副本发布和项目级 `replay` 等预留命令仍返回 `FEATURE_NOT_IMPLEMENTED`/4。顶层 `plan`/`diff` 已开放原生预览与重新核验；顶层 `apply` 仅接受绑定当前显式检查的技能文件安装计划。源命令通过 `skill plan` / `skill apply` 单独开放，需要显式 `--managed-root <专用测试项目/.aidock> --home <隔离数据根> --project <UUID> --scope <作用域>`；未绑定返回 `SOURCE_BINDING_REQUIRED`/4。源模式的事务目录固定在显式 home 下的 `local`，不会被个人 settings 的 Local Root 重定向。

源管理界面使用相同参数启动 `config`；源事务基础见 [v0.2 记录](docs/AIDock-源事务实施-v0.2.0-dev.md)，新增动作/引用范围/冲突修复见 [v0.3 记录](docs/AIDock-技能生命周期实施-v0.3.0-dev.md)。`skill references <UUID>` 只报告当前绑定内的声明引用；未知项目/离线范围使物理删除保持阻断。配置结构校验可用 `doctor --file <path> --kind profile` 或 `--kind skill-lifecycle --json`；它不代表依赖/运行/权限验收。

「Profile 与规则」编辑当前项目共享层，批量开关保留固定版本与完整包。`profile show` 读取当前配置/摘要；`profile plan --file <编辑请求>` 接受 `expected_sha256` 和完整 `profile`，确认复用 `skill apply --plan <UUID> --expected-digest <摘要>`。`profile resolve --file <层描述>` 只读解析显式 defaults/profiles/project/local/session 与身份/修订 catalog，不扫描全局配置、不建立持久关联、不执行工具。规则原生编译仍待完成，有规则的工具应用预览保持阻断。

项目源已保存后，另加 `--native-root <专用测试项目>`（当前 `.aidock` 的父目录），可用 `plan --all` 或 `plan --tool codex-cli` 生成完整包预览；`diff --plan <UUID> --expected-digest <digest>` 重新检查输入。相同绑定启动 `config` 后显示工具预览入口；`tool list` 查看适配器描述。默认预览只读。当前保存版本执行 `tool check --all --probe` 后，用 `plan --all --check <检查 UUID>` 生成可安装计划，再用 `apply --plan <UUID> --digest <完整摘要>` 确认完整技能文件安装。检查/源/目标/程序/版本变化会拒绝写入；未验收的原生字段语义仍阻断。`tool history`、`tool rollback plan --transaction <最新成功事务>` 与 `tool rollback apply --plan <UUID> --digest <摘要>` 支持回退及撤销。文件安装不执行代码，实际会话生效另行验证。

同一绑定下，`tool check --all` 检查项目工具文件，默认不启动进程；`tool check --all --probe` 在独立临时项目与空工具配置中初始化两款 CLI，核对已保存完整包的名称/描述/路径。`tool check --last` 和 `doctor` 读取最近记录并核对过期状态，不启动工具。隔离发现通过仍不等于实际项目会话生效，因此检查返回 `EVIDENCE_INCOMPLETE`/3；静态/发现失败返回 5，历史过期返回 `CHECK_STALE`/3。界面入口为「AI 工具 → 验证工具发现」，需在页面确认。

外部源桥接使用单独登记文件：`aidock skill bridge-check --file <bridge.yaml> --json`。登记只读扫描完整包，返回 `current_revision`、`approved_revision`、候选包和 `EXTERNAL_SOURCE_DRIFT`；来源角色必须明确声明为 external-source；只读检查不修改 pin。项目额外绑定 `--bridge-file` 和 `--copy` 后，可用 `skill plan external-adopt` / `skill apply` 显式采纳完整包；`external-select` 选择历史批准缓存，源回退保留批准历史。外部目录与登记文件不写回。

全局管理使用 `config --global-root <显式技能库 Config Root> --home <隔离数据根>`；它与项目绑定互斥。项目附加 `--library-root <技能库 Config Root>` 后，可在页面选择当前候选或历史精确修订，生成采纳计划。项目操作仅写项目源，库的观察备份放在项目 Local Root；库父目录的 OS 锁协调并发。库根需已初始化，且不能与项目源/事务根重叠。依赖/兼容/执行需求纳入 `semantic-v1` 摘要，完整依赖解析和运行检查仍待实现。

五副本演示：进入「同步与迁移 → 同项目多副本」，选择工作区根/服务端/客户端作用域，再选择本次源和目标。在预览中为 work3 的示例冲突选边或跳过，确认后目标共享源与生成物更新；本地路径、端口和环境历史保留。可模拟源修改使预览过期、目标写入中途失败、撤销上次同步，以及新会话/只读探针。路径来自 `E:\work`、`E:\work2–5`，差异与检查结果均为预设样例，未扫描或写入实际目录。

设计中的真实检查分四层：源与生成一致 → 工具发现 → 新会话加载 → 指定能力探测。实际接入沿用各目录已有的配置真相源和生成器；源同步成功只证明配置传播，不代表旧会话已加载。

回退演示：修改配置并应用后，在「时间线与回退」选择「回退到此」，预览并确认；「撤销上次回退」会恢复回退前的应用结果和已保存草稿。应用和回退弹窗都有“中途失败”选项，可检查失败后的自动恢复。旧插件版本可以按项目锁定，再从 MCP 配置选择较新缓存版本；其它项目继续使用原版本。

快照、安装缓存、目标文件、审计与 Git 同步均为模拟。原型不写本机配置、不执行 OS 隔离、不保存凭据值，也不执行程序降级。磁盘事务、重启恢复和真实工具生效按设计及开发计划另行验收。
