# 精确技能修订归档与恢复材料检查实施

版本：v0.72.0-dev；日期：2026-10-16；冻结设计：v0.24；Goal active。

## 修复的问题

已继承同一技能 A/B 版本，而本机停用声明引用尚未采纳的 C 时，旧快照按技能 ID 判断材料已有，可能漏存 C 正文。配置能重建，也不能据此证明精确修订可恢复。

现在按 ID、精确修订及完整包正文核验覆盖。明确保留且正文有效的版本不重复归档；缺少的全局继承修订单独保存完整附件到项目私有不可变缓存及 Git 归档。任意缓存文件、同 ID 的项目 owned/override/external 包不能替代所引用的修订。停用项目包若正文已损坏，同样不能创建假装完整的可恢复快照。

恢复草稿时保留历史继承主关联与已有版本，将 C 加入明确保留版本；共享 B、本机 C、停用状态及原始 Local 内容分别保留。归档脚本只复制原文。全局库不改写，未执行脚本，不恢复历史授权；两层已保存草稿仍使用原共同事务及回退/撤销机制。

## 检查与界面

`snapshot assess` 和对应 API 新增 `skill_revision_material`，只有安全状态及缺少的精确修订数量；不返回正文或配置值。`COMPLETE` 只表示被配置引用的技能修订有完整可核验材料，不表示插件依赖、当前授权、原生应用或完整项目 replay 已通过。

时间线分别显示历史配置重建、当前静态依赖、精确修订材料。缺正文或正文损坏显示阻断提示，禁用该观察下的草稿恢复入口；后端也独立拒绝恢复，不能通过跳过界面检查绕过。重新读取会清除旧观察。

旧快照保持可核验、可重建，不根据现有技能 ID 或当前全局库补造缺失修订。引用缺材料返回 `SNAPSHOT_DEPENDENCY_MATERIAL_MISSING` / 4。快照输入格式继续兼容 v1/v2，本次没有新增格式迁移。
