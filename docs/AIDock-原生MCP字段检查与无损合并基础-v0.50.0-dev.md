# 原生 MCP 字段检查与无损合并基础

版本：v0.50.0-dev。项目级配置只读检查已贯通 CLI、API 和管理界面；字段合并引擎已实现并通过测试，尚未接入原生写入。阶段 1 和完整 Goal 继续推进。

## 已开放的用户流程

在“AI 工具”选择 Claude Code / Codex CLI，点击“检查项目 MCP 配置”。分别读取当前绑定项目的 `.mcp.json` / `.codex/config.toml`，核对 `mcpServers` / `mcp_servers` 的独立服务器对象。界面展示名称、未托管归属、文件是否存在、结构问题和文件摘要，不展示配置值。

JSON 重复键（含转义后同名）、无效语法、非法服务器结构、TOML 重复定义、错误编码、超限文件及不安全路径分别返回明确诊断。某一工具配置有问题时仍保留另一工具的结果。`aidock-` 名称前缀和 TOML 注释均不证明归属，不会因此自动接管。

CLI：`aidock tool config --all`，或 `--tool claude-code` / `--tool codex-cli`，配合现有项目绑定参数。API：`POST /api/native/config`，仅接受所选工具集合，使用当前会话项目绑定与 CSRF 校验，不接受任意路径或正文。诊断成功但配置有错时，CLI 返回完整报告及 `STATIC_CHECK_FAILED`；API 保留完整报告供界面展示。

检查不执行工具或 MCP、不展开环境变量、不读取用户级或企业级配置、不修改项目文件，也不将原生配置正文存入 Local Root。配置存在、结构可读取不代表工具加载、连接、授权、隔离或能力已通过。检查保留技能草稿及当前工具应用预览；切换工具或项目后不复用旧结果。

## 无损合并引擎的实际范围

内部 `nativeconfig.Merge` 只允许独立的 `aidock-…` 服务器项。需要调用者持有的上次生成字段哈希；名称相同但未登记，即使字节相同也阻断。已登记项被删除或修改会报托管漂移。返回候选原字节和新的字段哈希，不自行写盘或授予执行资格。

JSON 按原成员和值的字节范围修改，不重建外围对象；非托管值及其排版保留。TOML 以配对注释标记独立生成表，保留其它表与手写注释。现有未标记的表、点键和内联表示不猜测接管；无法无损插入时阻断。标记内包含其它设置、标记被字符串伪装、或标记外的子表扩展同一服务器都会阻断。稳定排序和重复合并均已验证。

**引擎尚未连接实际原生 MCP 编译、Local Root 所有权登记、多目标事务或回退。** 目前界面与 CLI 只开放检查，现有项全部按未托管显示。原生字段写入的完整验收条目保持未勾选，后续必须与受管启动器、实际目标锁、事务恢复和权限校验共同接入，不能输出绕过启动器的直连配置。
