# 副本规则候选与联合恢复 · v0.31.0-dev

日期：2026-10-15。继续冻结设计 v0.24 的阶段 1D，阶段 1 与整体 Goal 尚未完成。

## 当前行为

内置 owned 编译器现在为每个目标生成完整技能目录及 CLAUDE.md / AGENTS.md 规则托管区块，使用该目标自己的候选源、全局默认、Profile 继承和本机覆盖。手写技能及规则托管区块外的正文保留。纯生成物修复同样支持规则，不采用发布者源、不推进共同基线。

跨副本预演将技能源、工具目录、规则单文件及共同基线绑定为精确独立根。先备份、共同加锁并设置持久恢复标记，再逐根写入；不声明跨目录瞬时原子可见。失败、进程退出、回退和撤销使用同一清单。恢复先核对全部冲突，退出后的人工修改会阻断并保留；不会从共同父目录捕获或覆盖无关文件。

管理界面显示每个副本的规则变化、托管正文、手写保留内容、规则恢复路径和事务规则文件数。发现确认框增加默认不勾选的「同时验证规则来源」。技能发现不自动启动规则会话；只在单独选择后，用 v0.30 已验收协议核对每个候选的独立临时会话来源。含任意 ASCII @ 的 Claude 完整候选仍不启动规则会话。L3/L4 始终 UNKNOWN。

## 接口与兼容

- 内置生成清单升为 schema 4，版本 1/2 的内置技能清单和版本 3 的外部返回清单保持可读；规则只允许在 schema 4 中出现。每次使用 v4 清单会重新编译并核对精确输出，重算清单摘要不能采纳改写规则。
- Coordinator 的根增加可选 `file:true`，目录默认省略此字段，因此旧记录摘要与事务桶不变化。单文件快照只能是 content 或不存在；目录/文件形状、路径和类型不一致拒绝。最多 97 个目录与 64 个规则单文件，不放宽旧目录上限。
- CLI：`replica generation check run --plan <生成 UUID> --digest <摘要> --probe --rule-probe`；`--rule-probe` 必须同时有 `--probe`。API：`POST /api/replica/generation/check` 的 `probe:true,rule_probe:true`。
- 逐副本检查增加独立必需门槛 RULES_LOADING；检查策略升为 v2，旧检查保留为历史并要求重新核对。检查仍不能授权安装或正式发布。
- 外部 `aidock-skill-mirror-v1` 合同保持技能目录范围。有规则要求时明确 RULES_TARGET_REQUIRED 阻断，不丢弃规则，也不把外部返回包自动提升为配置生成器。
- 新的五副本体验实例带有四份不同本机规则及 BOM/CRLF 手写文件；重复启动保留现有内容，不升级或重置旧体验数据。
