## 当前行为

联合应用快照可恢复为已保存草稿，先预览项目共享源与当前副本本机覆盖的逐项文件变化，再用精确计划与摘要确认。历史共享配置转为项目覆盖，清除命名 Profile 依赖；本机原始 profile.yaml 单独保存，保留注释、CRLF 和字节，不泄漏到共享层。文件化规则按原身份保留且不重复合并。继承/外部技能保留原来源身份并固定完整版本，不改写全局库。

仅保存草稿不会安装工具文件或恢复旧授权。工具重新检查、当前安装、项目权限和凭据仍走现行流程。独立回退可恢复操作前的已保存草稿，包括原来损坏的字节；撤销回退可重做恢复。原有知识、会话、审计、凭据、Git 及当前未管理文件保留，新不可变修订/批准缓存也不会因回退丢失。页面未保存编辑继续由现有草稿保护保留。

## 入口

```text
aidock snapshot draft plan <snapshot-id>
aidock snapshot draft apply --plan <plan-id> --digest <digest>
aidock snapshot draft history
aidock snapshot draft reverse <transaction>
aidock snapshot draft inspect
aidock snapshot draft recover
```

以上命令追加明确项目/作用域/副本/source/native/home 绑定参数和 --json。API 在 /api/snapshots/draft/ 下提供对应 plan/apply/history/reverse/inspect/recover，保留认证、Origin、CSRF 和逐请求绑定。管理界面在“时间线与回退”中提供快照恢复、草稿事务历史与中断恢复。公开报告含安全元数据、精确绑定根及文件变化，不返回正文、权限值、用途、命令参数或原生备份。

## 共同事务与保护

- 使用现有共享根锁、持久备份、精确旧/新树及摘要，项目 .aidock 和派生 Local Profile 根共同提交。任何预览后变更使整个方案过期。
- 第二根失败或进程退出后，普通源操作被共同恢复标记阻断；检查两根与人工外改后再共同恢复。人工冲突不强行覆盖。空历史检查不创建缺失本机目录。
- 当前项目身份必须有效一致；owner/scope、未来 schema、不受管本机文件和不可变缓存冲突明确阻断，不通过历史快照强行认领当前数据。
- 损坏当前 Profile 或 Local binding 时仍能重新启动控制台、读取归档及显式修复；启动保留路径/权威根边界检查，普通写入口仍完整校验当前绑定。读取失败清空旧成功状态和计数，修复后清除旧错误。
- 回退保留新增的不可变修订及批准记录；不复活撤销授权，不打开凭据库，不启动插件。
