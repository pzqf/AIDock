# AIDock

面向多项目、多 AI 工具的开发环境配置管理设计。当前仓库包含设计文档与单页交互原型，尚未实现 Go CLI、适配器写入或真实 MCP/模型连接。

原型可演示项目独立的技能/Profile/MCP 配置、净差异预览与应用、记忆敏感度和来源、会话与引用范围、插件授权、配置同步及回退。

封版冻结需求、行为契约、首期范围与验收条件。首期为 Windows、Claude Code + Codex CLI、手动五副本同步/诊断/恢复；精确工具版本、OS 隔离和磁盘恢复必须在实施时验证，设计封版不代表软件已经可写入真实工作区。设计变更须记录兼容性、迁移和回归并更新基线版本。

五副本演示：进入「同步与迁移 → 同项目多副本」，选择工作区根/服务端/客户端作用域，再选择本次源和目标。在预览中为 work3 的示例冲突选边或跳过，确认后目标共享源与生成物更新；本地路径、端口和环境历史保留。可模拟源修改使预览过期、目标写入中途失败、撤销上次同步，以及新会话/只读探针。路径来自 `E:\work`、`E:\work2–5`，差异与检查结果均为预设样例，未扫描或写入实际目录。

设计中的真实检查分四层：源与生成一致 → 工具发现 → 新会话加载 → 指定能力探测。实际接入沿用各目录已有的配置真相源和生成器；源同步成功只证明配置传播，不代表旧会话已加载。

回退演示：修改配置并应用后，在「时间线与回退」选择「回退到此」，预览并确认；「撤销上次回退」会恢复回退前的应用结果和已保存草稿。应用和回退弹窗都有“中途失败”选项，可检查失败后的自动恢复。旧插件版本可以按项目锁定，再从 MCP 配置选择较新缓存版本；其它项目继续使用原版本。

快照、安装缓存、目标文件、审计与 Git 同步均为模拟。原型不写本机配置、不执行 OS 隔离、不保存凭据值，也不执行程序降级。磁盘事务、重启恢复和真实工具生效按设计及开发计划另行验收。

运行状态与交互回归（Node.js 18+，无需安装依赖）：

```powershell
node demo/tests/regression.cjs
```

当前 58 项回归使用原型的完整内联脚本，DOM/计时器为替身；覆盖项目隔离、预览过期、分级、取消响应、授权、自动恢复、手动回退与撤销，以及副本冲突/共同基线、本地差异保留、整批恢复、生成漂移与分层证据。它们不代表页面布局、浏览器或外部集成验收。
