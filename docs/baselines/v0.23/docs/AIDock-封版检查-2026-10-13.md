# AIDock 设计封版检查

日期：2026-10-13。基线：**v0.23**。结论：本轮识别的设计阻断项已在设计和开发计划中关闭，可以冻结需求、行为契约、首期范围和验收条件。软件实现与运行验收另行进行。

## 复查发现与处理

| 项目 | v0.22 的不足 | v0.23 的处理 |
| --- | --- | --- |
| 副本身份贯通 | 注册映射和会话示例仍偏单目录，相同逻辑项目可能覆盖绑定/共享任务记忆 | project/scope/copy 绑定统一；会话固定 copy；记忆增加 origin_copy/visibility，缺归属条目待绑定 |
| 本机有效值 | 排除了 local 文件，但合并算法未完整包含本机覆盖层 | 共享层 → 本机层 → 临时层；桥接保留原整项覆盖语义；预览显示共享更新被 local 遮盖 |
| 存量运行治理 | 生成器可能生成直接启动/HTTP 项，却被误认为受 AIDock 安全门治理 | governed/external 分开；受管项必须走锁定 stdio 启动器；未支持 external 运行字段不新增/传播 |
| 恢复资产 | Local Root 被概括为可重建；注册、基线、快照及原始字节可能被误清理 | 单列受保护资产/引用清单；空间预检、提交标记、取消恢复、移除注册与 tombstone 保留 |
| 存储/路径 | 两根可同目录；控制台仅许数据根与真实项目写入边界矛盾 | 两根最终路径不重叠；按数据、注册 copy、已授权目标分别校验；不支持的 Local 文件系统拒绝写入 |
| 数据迁移 | 云盘单文件原子替换不足以防多文件混代；记忆 MCP 可能并发写正文 | 版本/哈希清单完整校验；正文导出/导入需与记忆 MCP 协调，缺能力不承诺完整迁移 |
| 契约一致性 | 自有 TOML/YAML 混述、Schema 示例缺版本、安装是 shell 文本、缺 mcp exec/退出码 | YAML 规范源 + Markdown 技能；明确外部格式边界；参数数组、版本化 Schema、计划和结果/退出码契约 |
| 首期/反馈 | 两个首期工具尚未定案；实施路径遗漏多副本；开关即生效/引导就绪表述过强 | 首期 Windows + Claude Code/Codex CLI；多副本诊断/恢复归阶段 1；生成与新会话验证独立显示 |
| 控制台/凭据 | URL token、内联原型与严格 CSP 混述；凭据导出违背默认不随行 | 启动 token 单次交换、会话绑定；正式前端不用 unsafe-inline/eval；v1 只导出凭据引用 |

## 实施入口与验收边界

这些是必须通过的实施门槛，当前没有已通过的声明：

1. Claude Code/Codex CLI 的精确版本、发现目录/优先级、托管字段与新会话加载证据；App/其它工具单独验证。
2. Windows 隔离原型、broker、目标运行时兼容，以及路径/链接/网络/子进程越界负向验证。失败须拒绝所需能力，不能静默降级。
3. 机器可读 Schema 与文档 golden 示例；写操作真实磁盘故障、中断、恢复期间外部修改和取消用例。
4. 五工作区真实登记与生成器暂存适配；先只读报告、再按计划逐步开放写入，不整目录覆盖、不更新/提交代码仓。
5. 阶段 2 的记忆 MCP 稳定正文导出/导入及 copy/敏感度/目的地过滤；不能满足则不开放对应治理能力。
6. 正式前端 CSP、访问认证、键盘/焦点/布局与浏览器验收。当前 Demo 的 DOM 替身回归不覆盖这些项目。
