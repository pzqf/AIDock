## 当前行为

普通 Profile 联合应用新增稳定的 applied_binding，安装的 MCP 启动参数带 --applied-key 和原 native-root。启动时从成功提交的应用快照重建原配置，不用后来保存的项目或本机草稿替换它。固定视图保存原分层来源、精确版本与完整包；不继承今天的全局默认。旧安装和独立 mcp client-config 沿用原来的当前源行为，不静默升级。

新增 aidock tool applied --json（追加显式项目绑定）及 GET /api/native/applied，时间线新增“已应用配置与已保存草稿”。报告展示安装绑定、原事务与快照、源/本机字节比较、原生文件和各工具连接的本次启动门槛。不输出配置正文、参数、用途或密钥。CURRENT 仅表示本次核对启动条件，不表示进程正在运行；字节相同不代表今天的全局/会话语义或技能 L3/L4 通过。

保存新草稿不停止已安装的固定 MCP。需要立即停止时，撤销项目授权或移除连接。下次应用使用重新检查的当前草稿，旧 argv 不能跳过新的安装身份。

## 当前权威与回退

- 原始归档必须有对应 committed 事务、完整原计划与摘要，prepared 意图不能启动。稳定绑定包含源、原配置层、项目/副本/根、完整会话选择、适配器与 AIDock 程序摘要；同输入保持幂等。
- 启动及每次有界协议传输持源、本机、产物、权限及原生目标锁，复用当前安装、独立授权、最新版本核验和完整产物检查。锁不跨上游等待或整个会话寿命。明确撤销使等待中的返回数据被拦下。
- 原生连接所有权和当前实际字段仍须与成功应用一致。删除、漂移、不同 copy、未知绑定或更换 AIDock 程序都不能继续使用旧参数。相同路径升级 AIDock 后须重新检查应用；本版本不自动迁移。
- 回退可以删除连接；撤销回退重新引入固定连接时，按其原视图及当前权威重新核验，不把不同的已保存草稿当作历史配置。撤销/授权变化、缺依赖或产物漂移保持阻断。混合多个应用绑定或旧/新模式的恢复明确等待协调。
- 原生备份仅物化到受限私有缓存；不进入普通技能源正文缓存。读取会写本机观察缓存/锁，不能宣称 Local 零写入。报告不启动 AI 工具或 MCP、不打开凭据库；归档核对仍使用本机 Git。
