# 项目诊断汇总与恢复导航 · v0.63.0-dev

控制台新增“项目诊断”，集中查看技能源合理性、配置来源与本机覆盖、两工具当前文件和已有生效证据、已登记副本数量及当前绑定可见的待恢复事务，并可进入对应管理页处理。

CLI 使用 `aidock doctor --project-status <绑定参数> --json`，认证 API 为 `GET /api/diagnosis`，两者使用同一个 Engine 报告。诊断成功返回报告；CLI 继续以 `EVIDENCE_INCOMPLETE`、退出码 3 表示尚未证明完整生效。原 `doctor` 和显式探测入口保持各自契约。

## 判断方式

- 当前技能与规则文件重新编译比较，不以旧检查记录的 L1 代替当前磁盘状态。
- 发现、实际会话、能力与隔离规则来源来自本项目已有检查。源、目标、版本或时间使记录过期时，当前结论恢复为未验证，旧结果只在历史详情显示。
- 安装后，当前文件可以已经一致，但安装前的检查已过期；刷新显式发现证据后再展示当前通过。
- 本机配置只汇总最终来源路径、覆盖来源和层级，不输出配置值或规则正文。
- 源、工具文件、MCP 连接和本目录发起的正式同步记录分别读取。多目录事务保护的目标须切换原发起副本恢复整批事务，不能引导为单目录源恢复。其它插件资产事务仍在原管理页处理。
- 单项源或历史损坏不会中断其余诊断，原始解析错误只输出错误码，避免把配置值带进报告。

## 读取边界

诊断不启动 CLI、生成器或技能，不安装、不授予权限、不恢复。当前文件检查不会保存新的工具检查记录，也不会替换原显式发现证据。底层读取沿用已有编译器、锁与本机观察缓存；项目源、工具文件和恢复标记保留。

各项依次读取，是本次观察，不是跨目录原子快照或安装资格。页面保存源后会失效旧汇总；读取失败不保留旧通过结果，迟到响应不会重新展示已失效报告。诊断入口等待项目初始化完成后开放。
