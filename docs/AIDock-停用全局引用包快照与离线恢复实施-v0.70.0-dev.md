# 停用全局引用包快照与离线恢复实施

版本：v0.70.0-dev；日期：2026-10-16；冻结设计：v0.24；Goal active。

## 本次变化

原始配置输入 schema 从 v1 升至 v2：对历史共享配置、当前有效配置和本机层的精确技能 pin，补齐项目尚未采纳的全局 owned 包。完整文件和附件存入项目私有正文缓存及私有 Git；它们与有效启用包分开，不进入当次工具安装。没有配置引用的库资产不额外收集；pin 本身也是配置引用，即使尚未声明启停。

身份、固定语义版本、清单、每份正文、重复/无关包、原生入口名均校验。归档读取、完整性核验和本机缓存重建包含额外引用包，脱离当前库即可使用。公开 CLI/API 只新增 reference_packages 数量，管理界面说明这是恢复材料，不显示正文或把它算作有效包。

恢复为已保存草稿时，将缺少的引用转为保留 global 来源的项目固定继承，并从已核对归档装入不可变版本缓存。共享/本机启停仍依照历史合并结果；不执行包内脚本、不安装工具、不恢复授权。回退还原原草稿，新增不可变缓存继续保留，因此首次恢复后的源树可以多出只含已核对旧版本的缓存，不能据此宣称整个源树没有任何新增文件。

原始输入 v1 兼容读取/核验；若旧归档没有未采纳引用的正文，继续返回 SNAPSHOT_DEPENDENCY_MATERIAL_MISSING，不读当前库补猜。共享与本机层对同一未采纳技能指定不同版本时，两份版本都归档，草稿投影返回 SNAPSHOT_REFERENCE_PIN_CONFLICT，需后续版本协调模型；不隐式选边。
