## 可用流程

在「跨副本」比较并保存逐项选择方案，进入「准备各目标 MCP」，分别备齐目标自己的包、安装、授权和固定运行时，再明确验证完整技能、规则、全部启用 MCP 的工具发现。点击「汇总所有目标完整检查」，只有每个原方案目标均有完整检查引用时，才能汇总并保存完整批次预览。静态检查不代替工具发现资格，不能漏选目标或省略未准备的启用项。

主页面「查看完整配置批次」可读取保存记录。历史列表始终是 SAVED、fresh=false，只表示保存过提案；必须重读原 UUID 与完整摘要，重新核对所有目标及现行授权，才能显示本次 CHECKED 观察。源、本机层、库、授权、固定运行时、工具或原生文件变化使旧批次失效；STALE 清空变化、工具/会话清单和应用身份，不显示部分目标为当前可用。

**此版本只保存/重读私有完整批次预览，can_apply 始终 false。** 完整批次写入确认、共同中断恢复及所选成员回退/撤销尚未接通，原 MCP 正式发布阻断继续保留。预览不会创建已应用快照、伪造成功日志、写规范源/本机覆盖/原生文件/共同基线，也不执行程序。内部编译观察、完整备份材料、空锁和提案在本机私有区，不承诺 Local 零写入。

## CLI/API

```text
aidock replica publication full-plan --file <全部目标检查引用.json> <绑定参数> --json
aidock replica publication full-show --publication <完整批次 UUID> --digest <完整摘要> <绑定参数> --json
aidock replica publication full-history <绑定参数> --json
POST /api/replica/publication/full-plan
POST /api/replica/publication/full-show
GET /api/replica/publication/full-history
```

full-plan 请求只接受 plan_id、digest 和 checks。checks 中每项包含 copy_id、preparation_id、preparation_digest，与原方案目标一一对应；不接受客户端树、目录、命令、授权、事务或原生正文。full-show 只接受 publication_id、digest；重复键、别名、null、未知字段和缩减目标拒绝。

公开结果只含绑定、检查引用、工具/MCP 名称、摘要与文件变化元数据，不含配置值、清单正文、权限值、启动参数或密钥。完整方案、共同事务提案和原生备份保存在受限私有目录。结构化读取核对原共同事务；重算描述摘要不能改变发布者、目标、源/基线或根绑定。重读再用原完整编译器核对材料，不用历史结构完整性冒充工具资格。
