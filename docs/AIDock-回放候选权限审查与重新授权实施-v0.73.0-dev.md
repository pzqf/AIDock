## 本次行为

完整项目回放需要先针对冻结候选核对当前依赖与权限。现有授权包含项目、副本、物理源目录、完整源和最终配置摘要；不能先写历史源来取得授权，也不能借用历史批准。

本次从原私有 Git 快照重新构造候选，保持当前已保存源、Local 和工具文件不变；按候选的精确配置检查当前安装、安全证据、权限、工具合同、密钥引用名称及固定运行时。当前安装缺失的 MCP 仍列入审查，不会消失成“无需授权”。公开结果不包含源/规则正文、原用途或凭据值。

明确确认后，授权及审计写入原项目权限权威库。同名现有授权会被替换，授权摘要变化会使现有连接需要重新检查和生成；被替换授权的运行时证据失效。候选授权在不同的当前配置下保持失效，只有源和本机层实际解析为精确候选时才匹配。此过程不启动插件、不交付密钥、不写原生工具，也不等于完整项目 replay 已实现。

撤销继续使用项目授权入口；草稿恢复/回退不会回退权限或审计。恢复旧授权仍须本次重新核对并确认。Tier 0 自有本地 Node 的非隔离选择、工具合同和密钥交付仍分别确认，其它安装、隔离、运行时及启动门槛保留。

## 入口与绑定

```text
snapshot replay review <snapshot-id>
snapshot replay permission plan --file <request.json>
snapshot replay permission apply --plan <id> --digest <digest>
```

请求包含 `snapshot_id`、`candidate_digest` 和 `authorization`。授权字段沿用现有 action=grant、name、expected_sha256、expected_review_sha256、用途、Public 级别及目标合同和各项独立确认。没有自动同意模板。当前候选入口不提供 grant 以外的动作，普通撤销/恢复入口保留。

API 对应 `/api/snapshots/replay/review`、`/permission/plan`、`/permission/apply`，均为已认证 POST，并沿用 Origin/CSRF 与精确项目绑定。重复键、别名、空值、未知字段、替代根或自定义命令拒绝；确认只接受本机保存的计划与完整摘要。

候选摘要同时绑定当前源/Local 原件和投影后的源/Local/配置。每次审查、预览和确认均重新读取归档，持有源、本机和产物锁；源/本机草稿、安装、授权、账户或审查输入变化会阻断。候选计划不能从普通当前源授权入口确认，不能跨副本或借其它快照接管根目录。

## 界面

时间线新增“审查回放候选授权”。选择具体 MCP 后可展开本次权限、工具合同和运行环境，填写新用途并逐项确认。预览显示具体插件、是新增还是替换、影响及完整摘要；确认和取消分开。取消保留用途，输入/确认变化清除旧计划，失败重读清除旧观察，迟到响应不覆盖新状态。

确认后刷新来源及候选状态，清空确认勾选；即使授权成功而后续重读失败，也明确报告“授权已记录”，不会误报未提交。完整应用回放仍明确显示未开放。

## 审计过期修复

真实流程发现：预览授权后合法撤销，再确认旧计划，会先用旧计划树检查新事务锚点，误报审计损坏。现在在原权限库锁内先核对当前权威：当前链有效而原件变化，返回 PLAN_STALE；真正删除审计或破坏当前链，仍报告完整性失败。撤销和后续记录不被覆盖，原审计门槛保留。
