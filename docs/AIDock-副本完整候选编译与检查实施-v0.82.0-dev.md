## 使用流程

跨副本逐项选择后，进入「准备各目标 MCP」。目标自己的完整包、安装、授权和固定运行时就绪后，自动展开「编译并核对完整候选」。使用目标全局库、extends、本机层与候选源，编译完整技能、规则以及全部启用 MCP 的 JSON/TOML 连接；即使首个依赖失败，也保留完整请求集合，不省略其它启用项后宣称成功。

默认「编译并静态检查」不启动程序。点击「验证候选工具发现」后需另行确认临时项目中的工具发现；规则来源检查还有独立勾选。此流程只运行已安装工具的发现/来源协议，不启动 MCP 或技能脚本，不调用模型。取消确认不运行探测。

结果包含当前目标、候选与检查摘要、两工具的分层发现/规则结论、全部启用 MCP 的依赖门槛和原生文件变化元数据。源、规则正文、手写 JSON/TOML、命令参数和凭据值不进入公开检查摘要。完整编译材料和原生前后镜像保留在目标本机受限私有区。

检查不会写入规范源、本机覆盖或原生文件。`CHECKED` 只表示本次完整候选通过，`can_apply` 始终为 `false`。正式批次仍需固定应用视图与共同提交/恢复；原有 MCP 正式发布阻断保留。

关闭/重新打开同一目标候选时，页面只保留检查引用，需要明确「重读原完整检查」才重显结论。刷新页面后的引用持久入口尚未提供；CLI/API 可用原检查 ID 重读。修改工具选择、重新核对失败、目标/授权变化或迟到响应会清除旧成功。父弹窗更新不覆盖子面板自己的禁用门槛。

## CLI/API

```text
aidock replica candidate prepare --file <完整检查请求.json> <绑定参数> --json
aidock replica candidate prepared --file <重读请求.json> <绑定参数> --json
POST /api/replica/candidate/prepare
POST /api/replica/candidate/prepared
```

完整检查请求：

```json
{
  "plan_id": "已保存副本处理方案的 UUID",
  "digest": "方案完整摘要",
  "copy_id": "明确选中的目标 UUID",
  "preparation": {
    "tools": ["claude-code", "codex-cli"],
    "probe": false
  }
}
```

探测时明确 `probe: true`；同时核验规则来源时另加 `rule_probe: true`。仅接受完整范围，拒绝 `skills-rules` 缩减、重复键、别名、null、未知字段、自定义根/树/命令。重读请求使用同一 `plan_id/digest/copy_id`，另加 `preparation_id`，没有探测开关。

CLI/API 共用原副本、配置候选和原生编译器。源方案只从已保存且重新验证的逐项目标树重建；客户端不能注入编译树。检查前后重新核对源/配置层、所有连接与原生 MCP 文件、归属记录以及 AIDock 程序摘要，拒绝混合观察。重读不重跑工具，过期时清除可用变化、标记历史检查并保留安全错误码。依赖未就绪的阻断观察也绑定原生 MCP 文件，不会因提前退出而漏掉后续手改。
