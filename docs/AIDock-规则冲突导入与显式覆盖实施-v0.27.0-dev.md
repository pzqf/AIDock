## 冲突处理

AI 工具预览遇到已登记托管区块漂移或未登记区块时，三个操作都在页面显示明确边界：

- 「稍后处理」清除本次决策，原生文件和共享源均不写，后续仍会阻断。
- 「保留手改并合并到源」读取只读区块正文，打开 Profile 导入草稿。可选择“以手改区块替换共享规则列表”或“追加到现有共享规则”，可继续编辑；点击 Profile 保存预览后只写 `.aidock/profile.yaml`，原生文件仍待单独预览、规则加载检查和安装确认。
- 「覆盖回规范源」将当前完整文件树摘要和工具身份写入决策，重新生成预览；若文件在决策后变化，PLAN_STALE，不能以旧摘要覆盖。应用前和事务内再次核对同目录 `AGENTS.override.md` 等优先级输入。

导入通过同一 Profile 源事务，保留源快照、回退点、草稿和外部修改保护。CLI 默认将托管区块正文按空行分段形成有序规则；界面通过 `merged_rules` 保存用户实际编辑后的完整列表，追加不会再重复添加原正文，替换显式设置规则覆盖语义。观察正文必须与 SHA256 绑定文件的实际区块相符。导入不是原生文件写入授权，也不自动把规则升级成真实会话证据。

CLI 计划支持 `native_rule` 的工具、SHA256、正文和 `replace`/`append` 模式；原生 `tool check` / `plan` 支持逐工具 `rule_resolutions`。默认不接受路径参数，不从目录复制整个文件。规则导入只读取绑定项目 `.aidock` 同级的固定 `CLAUDE.md` 或 `AGENTS.md`。
