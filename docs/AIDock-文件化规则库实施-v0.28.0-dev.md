# 文件化规则库 · v0.28.0-dev

日期：2026-10-15。继续冻结设计 v0.24 的阶段 1C，Goal 保持 active。

## 当前行为

项目与本地全局技能源可在 `rules/index.yaml` 登记有序规则。每个规则有固定 UUID、展示名称和启用状态，正文独立保存在 `rules/<UUID>.md`，不执行内容、不接受任意文件路径。原有 `Profile.rules` 继续兼容；当前共享层的确定顺序为内联规则在前、已启用文件按索引顺序在后。`rules_override` 对该层的完整规则列表生效。

「Profile 与规则」现在可新建、命名、编辑、排序、启停及移除规则文件。旧内联列表可显式转成文件草稿，保留正文与原有效顺序。取消预览和关闭窗口保留当前标签页草稿；外部改动返回 PLAN_STALE，不覆盖编辑。只有确认保存才共同写入 Profile、规则索引和正文，沿用源事务、完整快照、失败恢复、回退和撤销。

未登记文件只提示、不自动编译、不接管、不移除；登记文件缺失、索引损坏、重复身份、越界身份、保留托管标记和非法编码明确阻断。规则库观察摘要覆盖整个目录，预览后源变化由原事务再次拦截。

已有文件规则时，原生冲突导入须显式提交完整合并草稿和规则库摘要。界面选择替换会展示原文件移除，选择追加把导入正文放在文件列表末尾；最终编辑由用户确认，不能重复注入原正文或改变已有顺序。

## CLI 与编译

`profile show` 返回 `rule_files`、`rules_sha256` 与 `unmanaged_rules`。`profile plan --file <请求>` 支持可选 `rule_files` 完整列表与 `expected_rules_sha256`；新条目的空 id 在预览时分配 UUID，确认仍用 `skill apply --plan <id> --expected-digest <摘要>`。不提供 `rule_files` 的旧请求保留规则库。

同一份已保存正文进入两工具规则托管区块，停用规则与未登记文件不会混入。未登记文件的警告不会代替缺失的工具发现、规则加载或安全语义证据。Codex CLI 0.162.1 仍须显式通过隔离规则加载检查才开放文件安装；Claude Code 规则加载和实际项目 L3/L4 继续显示 UNKNOWN。

机器 Schema 为 `rule-library` v1，附有 golden YAML。该实现没有更改 Profile v2 的自有字段，也没有把软件版本当作设计版本。
