# AIDock 外部返回包接入副本预演实施

日期：2026-10-15。版本：v0.20.0-dev。设计基线 v0.24 保持冻结。

本轮完成阶段 1D 的一个受限接力：v0.19 已暂存并校验的外部生成器返回包，可以被副本管理读取，映射到每个目标副本的独立工具目录候选，并进入现有联合预演、回退和恢复链。该入口只消费当前 `PASS` 校验记录，不启动外部程序，不安装工具文件，不修改登记项目、共同基线或真实工作目录。

## 可用入口

CLI：

```text
replica generation external-stage \
  --plan <副本候选计划 UUID> \
  --digest <副本候选摘要> \
  --stage <已校验生成器暂存 UUID> \
  --stage-digest <生成器暂存摘要>
```

API：

```text
POST /api/replica/generation/external
{ "plan_id": "...", "digest": "...", "stage_id": "...", "stage_digest": "..." }
```

管理界面在「同项目多副本 → 使用已校验的外部返回包预演」提供同一入口。先在「AI 工具 → 外部生成器」完成 v0.19 的暂存和返回包校验，再在当前副本比较结果中逐项选择差异处理，点击「读取可用返回包」，从下拉列表选择当前通过校验的返回包。预览时重新解析显式决策并核对输入与返回内容，生成候选后仍需确认独立预演。取消确认保留处理选择，不创建预演会话；读取失败清空旧选项并允许重试。

## 安全和一致性边界

- 生成器暂存必须处于 `STAGED`，存在当前 `PASS` 校验记录，且返回目录的观察摘要仍与记录一致；缺失、过期、失败或变化均阻断。
- 暂存的源根、owner、scope 必须与本次副本候选选择的源副本一致。
- 每个目标的完整 owned 技能身份、名称和 revision 必须与外部暂存输入完全相同。目标独有技能、集合差异、排除导致的缺口不会自动删除或猜测，直接阻断。
- 每个工具只从固定 `.claude/skills` 或 `.agents/skills` 子树提取完整包，二进制、附件、空目录和权限继续由完整树摘要绑定。
- 目标目录仍经过原有占用、所有权、人工漂移、保留项和 native 语义检查；本机排除和手写项继续保留。
- 生成清单使用 schema 3，绑定暂存摘要、校验记录 ID 和返回树摘要。源、目标、外部返回或校验记录变化会使候选过期，不能建立新的预演。检查和确认前重建完整目标与归属清单，重新计算本机记录摘要不能采纳未批准内容。
- 候选检查报告新增 `EXTERNAL_GENERATOR_OUTPUT=PASS` 仅表示返回包完整性和输入绑定通过；不表示外部程序确实执行，也不授予发布权限。正式发布门槛仍为 `BLOCKED`。

## 故障和恢复

外部输出在预演确认前变化时，重新核验返回 `GENERATOR_STAGE_STALE`，不创建新会话。已创建的独立预演仍沿用现有逐目录恢复标记、批次回退和撤销；恢复清单中保存 schema 3 生成摘要，即使原生成清单记录暂时不可读也不会扩大恢复范围。

本轮没有实现外部程序执行、网络隔离、真实项目写入、正式五副本发布、L3/L4 会话生效或历史垃圾回收。五个真实工作目录没有被扫描、修改或用作测试。

- `go test -p 1 -race -count=1 ./...` 全仓通过；replica 193.899 秒、generator 21.643 秒。`go vet -p 1 ./...`、Windows 构建与 Linux amd64 交叉编译通过；Linux 仅证明可编译。
- 十组前端状态回归、全部前端 JS 语法检查和 Demo 58 项回归通过。前端覆盖当前 PASS 筛选、取消后继续选择、resolve→external API 接力、加载失败清空与重试。
- Windows 实际 exe 与内置浏览器走通四目标、两工具的离线返回包候选、联合预演、整批回退及撤销回退；四个技能源、八个生成目录和一个独立基线根共同恢复。测试二进制附件、空目录与手写文件保留。
- 浏览器确认前对独立返回包施加字节变化，返回 `GENERATOR_STAGE_STALE`，未建立新会话；恢复精确原字节并重新校验后可重新读取、选择和预览。取消与过期阻断后，共有两条成功预演（CLI/浏览器各一），各保留应用、回退、撤销三条完成事务。
- 浏览器服务重启可读取原历史；480 像素窄屏的文档宽度与滚动宽度一致，没有横向溢出，最终页面无 console error。验收截图保存于 `.artifacts/aidock-replica-v0.20.png`。
- 测试技能带有不执行的 `scripts/helper.py`，原生安装语义检查按预期报告 `DYNAMIC_DEPENDENCIES_UNVERIFIED`，候选检查为 `FAIL`、CLI 返回 5。离线完整性 `PASS` 不覆盖动态依赖、实际外部执行、网络隔离或工具会话生效；正式发布按钮保持关闭。
- 真进程 `os.Exit(92)` 中断后，删除原暂存返回目录，新 manager 仍能恢复已建立的独立预演。已建立会话在原生成清单记录缺失时仍可回退与撤销；重算被改写生成清单摘要不能通过检查或开始预演；目标独有技能导致完整输入不一致时保留诊断，不删除技能。
- 完成后五个原始测试副本、原输入包、运行依赖及适配器共 178 个受保护条目字节/目录完全不变，原共同基线不变，无未完成预演。未触及 `E:\work`、`E:\work2`–`E:\work5`。

CLI/API 路由与既有副本入口共用同一后端。当前输出协议仍只接受完整包镜像，逐目标启用集合必须相同；更通用的转换生成、实际执行、网络隔离及正式批次发布不在本轮完成范围。
