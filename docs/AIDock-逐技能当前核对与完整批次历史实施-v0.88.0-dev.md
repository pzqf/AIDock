版本：0.88.0-dev；日期：2026-10-18；设计基线 v0.24。阶段 1 总验收未完成，Goal active。

## 问题与结果

完整副本同步会保存目标候选检查，原技能页只读取独立工具检查，实际安装成功后仍可能显示尚无检查记录。现在技能页和 AI 工具的“核对状态与历史”统一读取当前文件、最近独立检查、原成功完整批次的当前成员候选。当前 L1、独立发现和历史候选分别展示；历史 L2 不填充当前 L2–L4，不产生新应用资格。

```text
aidock tool evidence <明确绑定参数> --json
GET /api/native/evidence
```

原 tool check --last 及 /api/native/check/latest 保留独立检查语义。新读取不启动 AI 工具或 MCP；历史快照通过本机 Git 读取。不读取密钥，不写项目源或原生文件；普通编译观察仍可能写本机 blob 与空锁，不承诺 Local 零写入。

## 证据身份与失败处理

- 当前观察复用双工具技能/规则编译和逐包比对，读取前后重新核对输入。清空观察的 digest/expires，不保存检查记录，不替换最近独立检查。
- 原批次引用来自已核对项目快照与实际共同提交；再按原描述、真实提交证明、当前 copy 和源根、原私有 preparation 摘要及嵌套检查身份验证。原生漂移不抹去原批次历史。最多列最近 64 个相关批次，明确显示截断。
- 历史读取不要求今天的草稿、宿主二进制或授权仍与原候选一致；始终标记为历史，不能消费为安装资格。新草稿或另一技能修订不会借用历史通过标记。
- 已应用视图、完整批次历史、最近独立检查分别报告可读状态。某部分损坏则 status=PARTIAL、对应 UNAVAILABLE、安全错误码；不采用该部分的部分结果，不输出损坏正文。当前编译本身失败仍返回错误；取消不伪装成功。
- 缺少 copy 可核对当前文件，不编造副本和批次证据。API 只接受认证 GET 与原明确绑定，不接受额外查询范围。CLI 与 API 使用同一引擎。

## 管理界面

技能卡按最终选中完整修订和原生名核对 L1–L4。有效且身份、源快照、目标及工具二进制完全匹配的独立检查才可补充当前 L2；完整批次候选只列历史。AI 工具逐技能行明确区分文件和隔离发现。

历史入口只使用当前活动登记打开原发起副本，不接受任意路径。未保存草稿继续走原导航保护：在新标签页打开，原页草稿保留。迟到响应、失败读取、切换绑定和源刷新清除旧结果。
