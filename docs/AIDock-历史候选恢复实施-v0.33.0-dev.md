控制台重启后，在跨副本页展开“全部发布预检记录”，打开一条记录并核对有效性，再选择“恢复这份候选”。恢复使用记录绑定的 generation UUID 和完整摘要，不重新生成候选，不采用页面当前比较的选边，也不改变正在登记的源、目标或共同基线。查看当前候选后，预演仍需单独确认。

## 两种有效性

候选和检查证据分别核对。检查因有效期、工具程序或检查规则变化而过期时，如果源、目标、基线、本机层、适配器和完整生成内容仍一致，原候选可恢复后重新检查；历史通过结论保留过期标识。新的检查仍绑定同一候选摘要。

候选本身过期时，保留原决策、逐目标生成内容和变更清单供只读查看，禁用检查、探测和确认预演。必须重新比较并生成才能继续。损坏、丢失或不属于当前项目/作用域的清单直接返回错误，不能借恢复绕过确认或写入门槛。

恢复报告包含原源和目标副本的身份、名称及根目录。历史预览使用这些记录，不用当前页面另一次比较的名称；技能没有可靠历史名称时显示稳定 UUID。共享 Profile 和规则组显示固定含义。当前候选与正在查看的检查记录各自显示 ID/摘要，并明确是否对应。

## CLI 与 API

```powershell
aidock replica generation reopen --check <检查UUID> --managed-root <项目.aidock> --home <测试home> --project <项目UUID> --scope server --copy <副本UUID> --json
```

对应 `POST /api/replica/generation/reopen`，请求只含 `check_id`。返回 generation、check、source、targets、current 和可选 reason；CLI 的候选过期返回 PLAN_STALE、退出码 3，并保留只读结果。current 只表示候选输入仍有效，不表示检查通过、已应用、正式发布开放或新会话生效。旧的 generation show 继续仅供清单读取，不能代替本入口的当前核对。

新路由沿用本地会话鉴权、CSRF、固定项目绑定和严格请求解码。读取不启动工具、外部生成器或技能脚本，不建立预演事务。确认时仍由现有后端重新核对并执行独立目录事务，发布与安装资格不增加。
