# 统一回退入口与副本选择 · v0.78.0-dev

更新：2026-10-17。Goal active，阶段 1 与 S1-20 保持部分实现。

## 行为与入口

顶层 `aidock replay <snapshot>` 在当前明确绑定中匹配项目应用快照或正式副本批次。项目默认只读审查，返回 `REPLAY_CHECK_REQUIRED`；不会自动授予权限、启动核验、安装依赖或写入项目。完成原候选的当前授权、固定版本和全部工具检查后，才可生成共同提案。副本默认预览原始发布的事务前状态，`--copies` 只选择原批次的目标成员及相应共同基线。

```text
aidock replay <项目快照ID>
aidock replay <项目快照ID> --prepared <检查ID> --digest <检查摘要>
aidock replay <批次或事务ID> [--copies <copy-id1,copy-id2>]
aidock replay <同一节点> --plan <提案ID> --digest <提案摘要>
aidock replay <同一节点> --plan <提案ID> --digest <提案摘要> --confirm
```

追加当前项目的明确绑定参数；项目快照还需 `--native-root`。`--kind project|replica` 可明确命名空间。同一 ID 多义或任一需读取的命名空间损坏时不猜测。`POST /api/replay` 使用相同 engine，正文禁止覆盖根、项目或作用域；写入必须 `action:apply`、完整提案摘要及 `confirm:true`。预览、重读与确认不得换节点或成员。

时间线的项目共同回放预览/重读/确认已使用统一 API。跨副本正式记录新增成员勾选、恢复差异、重新核对和单独确认；选择变化立即清除旧提案及同意状态。显示副本名称和工具类型，技术路径与摘要保留在展开详情中。旧 scoped 恢复入口保留。

## 事务与恢复

- 原始发布节点可在局部回退后再次使用。仅最新成功的回退或撤销事务可撤销，旧回退返回 `REPLAY_UNDO_STALE`；这不是完整任意历史时间点重建。
- 只恢复所选成员的原始变化及对应 pair 基线；未选成员及发布者保留全部当前字节。原批次全部根仍参加锁定、过期核对及中断屏障；任何根无法安全观察则阻断。
- 所选成员必须仍在当前登记中、根与分支一致、项目身份有效；发布者、未知/重复/空成员和任意目录拒绝。
- 当前字节须匹配原事务的前镜像或后镜像；不覆盖未协调的人工修改。共同事务失败整批恢复本次变化，恢复阶段只作结构性身份检查，不复活旧授权。
- 私有提案除摘要外，还从原成功事务重新推导所选 after-image；改写两个本机摘要不能扩大成员、基线或内容。旧确认入口不能绕过该绑定。
- 本机覆盖、安装授权、会话、凭据和审计不回退；局部回退形成共享差异，不自动向其它副本传播。预览可写本机观察/提案记录，不能宣称整个 home 零写入。
