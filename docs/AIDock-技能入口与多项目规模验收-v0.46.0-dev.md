# 技能入口与多项目规模验收

版本：v0.46.0-dev。状态：常用技能 CLI、库关联断点及功能规模样例已实现并验证，阶段 1 和整体 Goal 继续。

## 使用结果

已登记项目可直接使用 `skill list`、`skill show <UUID>`，无需再知道 `managed-list` 特殊入口。`list` 保留与旧入口一致的完整状态结构；`show` 返回稳定资产、包文件清单、描述及共享/有效选择，`show --file <包内路径>` 读取正文或附件，二进制只返回元数据。只在显式项目、全局或登记入口绑定内解析，不按同名猜测身份。

`skill enable/disable <UUID>` 已替代预留占位，共用源 Manager.Plan，生成同一形态的持久预览；确认仍通过 `skill apply --plan <UUID> --expected-digest <摘要>`。源保存不安装工具，也不影响其他项目。缺少或不符摘要、源变化、未恢复事务和现有静态门槛继续阻断。更高配置层可能覆盖共享开关，预览内保留有效配置和检查。

显式 `--manifest` 继续保留只读 candidate locator 合同；不将盘点候选冒充稳定 ID。`scan` 只按清单盘点，已绑定资产使用 `list`；候选模式拒绝文件读取参数，资产模式拒绝生成镜像盘点参数。`managed-list` 保留兼容。修正 `--native-root` 帮助，说明安装需要独立检查、预览和确认。

补充 [技能管理入门](./AIDock-技能管理入门.md)，体验启动器重用已有数据时使用规范 `skill list` 入口。

## 规模样例发现的修复

过去在全局库已有技能时，库默认层的固定版本引用会被错误当作未知项目资产；新项目关联库失败，无法顺畅进入界面采纳。现在从同一份库树观察中校验已登记身份及完整不可变修订，作为层解析可用的版本目录。项目仍只把明确采纳的完整包放入自己的有效资产集合；库可见版本不会自动写入、启用或导出为项目包。

有效配置若要启用未采纳的库资产，返回 `PROFILE_SKILL_ADOPTION_REQUIRED`，静态检查显示失败；用户需先明确采纳，或在项目/本机层停用。真正未知 ID、不可取得版本和损坏修订继续阻断，配置层摘要继续绑定旧预览。已有覆盖和选定历史修订按稳定身份处理。

内置浏览器同时发现，已展开的全局候选和外部批准记录会把技能列表挤到很下方。两类来源信息现在默认折叠，仍保留版本选择和历史入口；库错误提示保持可见。
