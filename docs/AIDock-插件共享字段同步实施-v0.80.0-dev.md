## 行为与边界

插件清单字段可声明 `sync: shared` 或 `sync: local`，省略时保留各副本原值。这是字段所有权声明，不是执行、安装或权限授权。示例：

```yaml
config_delivery: env-json-v1
config_schema:
  languages:
    type: multi-select
    options: [go, typescript]
    sync: shared
  index_dir:
    type: directory
    sync: shared
  port:
    type: integer
    sync: local
```

只有当前锁定产物中已经核验的清单才提供声明。每个插件形成独立 `plugin-config/<登记名>` 共享组，两端须各自核验相同清单 SHA256、完整产物 SHA256 和排序后的字段清单。缺失或不匹配返回合同不匹配，不解释成删除，不复制安装、权限、凭据或会话。

共享组只投影项目共享层的原始覆盖与字段删除声明；不物化 schema 默认值，不投影全局或本机有效值。空数组、null 与缺失分别保留。采用源时，选中组内缺失的字段会移除目标对应的共享覆盖，未声明字段和其它插件保留。目标项目层存在整插件删除声明时，先明确协调，不能通过同步隐式拆分其本机字段边界。

目录只接受 `${PROJECT}` 及其规范相对子路径，每个目标后来按自身项目根展开。共享原始值总量最多 16 KiB。硬编码 Windows/POSIX/UNC 路径、HOME/SECRET 等其它变量、回环地址及已识别的凭据特征会阻断整个声明共享组，报告安全错误码，不把其余值当作删除候选。无法识别的普通字符串不因此获得“无秘密”的保证；真实凭据继续走独立 OS 凭据库。

三方比较使用该插件组自己的共同基线；旧基线不虚构新增组。源/目标单边、双方冲突、缺合同和阻断状态分别显示，逐项选边，不按修改时间决策。界面显示字段所有权、移除语义、原始变量与两端精确合同，也指出仍被目标本机覆盖遮盖的字段。被阻断组只可跳过。

本增量复用现有候选、当地生成、预演及正式批次事务。已声明字段可以随明确的“仅技能与规则”批次更新共享源；MCP 原生连接、本机安装和授权保持原状。此流程不会把配置保存冒充为 MCP 已重新应用。**完整 Profile/MCP 定义、精确版本锁的跨副本发布，以及逐目标重新授权后的 MCP 联合应用仍待完成。**
