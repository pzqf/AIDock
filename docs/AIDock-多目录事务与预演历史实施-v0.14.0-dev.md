# 多目录事务与预演历史实施

2026-10-14，开发版本 **v0.14.0-dev**。需求基线仍为 v0.24，本次继续阶段 1D。正式跨项目发布保持关闭，已有项目与真实共同基线不修改；`E:/work`、`E:/work2–5` 未扫描、未修改，也未参与测试。

## 已交付

副本预演不再以一个共同父目录作为写入边界。每个目标技能源和预演共同基线都有固定的绝对根、独立的目录键，计划绑定完整根清单和事务目录。拒绝重叠根、卷根、链接/reparse point、未登记目标和文件/目录类型互换。

`workstore.Coordinator` 按确定顺序取得所有根的 OS 锁，与单目录 `Store` 共用锁。任何根不可用或被占用时释放已取得的锁；不会持锁等待另一半目标。每个根的完整前后包都先进入不可变本机备份，所有输入、全部备份和确认摘要检查通过后才准备持久日志。

准备日志写入后为每个根建立旁路恢复标记，全部标记成功建立后才替换目标。标记在根之外，目录被移走或根本身不再存在时仍可见。不同 Local Root 打开的技能保存、原生导出和单目录恢复会阻断，必须从原副本事务入口共同恢复。正常提交记录先保存，再收口标记；提交已保存但标记清理中断时仅继续收口，不倒退已提交结果。

可见性仍是逐文件替换，不声称多个目录能在同一瞬间切换。恢复先检查全部根、全部备份、标记身份及所有受影响路径，再开始共同恢复。任一受影响路径有外部修改就停下并保留冲突。回退只恢复事务触及的路径，保留新增加的无关文件；技能、启停/退役记录与预演共同基线使用同一个提交和恢复点。

版本 2 预演使用多目录事务；已有版本 1 预演继续由原 `Batch` 读取、回退、撤销和恢复，不转换旧记录或丢弃备份。恢复只依赖已保存的候选与完整包备份，发布者目录消失也不会重建或改写发布者。

管理页新增「全部副本预演记录」和「独立目录与共同恢复范围」。可打开旧记录，再预览并确认该次预演的回退/撤销。历史和计划只读读取本机日志，不依赖目标根存在；目标父路径失联时仍展示记录及原因，等原目录恢复可用后重试恢复。CLI/API 使用相同后端。

## 入口

已有 `replica resolve`、`replica rehearsal run/plan/apply/recover` 保持参数兼容。新增：

```text
replica rehearsal history
replica rehearsal show --session <预演 UUID>
GET  /api/replica/rehearsal/history
POST /api/replica/rehearsal/show {"session":"<预演 UUID>"}
```

新预演回退计划的 `kind` 为 `coordinated-roots`，包含 `bound_roots`；旧版计划继续为 `native-targets`。二者都只能从对应预演的回退确认入口执行，不能作为实际项目发布计划使用。所有 API 继续校验本机 Host、Origin、会话和写请求 CSRF，严格拒绝未知 JSON 字段。

## 验证

测试使用独立 `t.TempDir()` 和仓库 `.artifacts/` 体验项目，覆盖完整包二进制/空目录、共同基线、回退/撤销、手写项保留、过期目标、缺失备份、取消、锁冲突和已消费计划。子进程在准备日志、第一份标记、首目标完成、持久提交和首标记清理后实际退出；新进程恢复通过。恢复中再次退出、外部编辑冲突、目标根/父路径失联、跨 Local 单目录写入阻断及发布者消失另有回归。

Windows 验证命令：

```powershell
$env:GOMAXPROCS = '2'
go test -p 1 -race ./...
go vet -p 1 ./...
go build -p 1 -o .artifacts/bin/aidock-v0.14.exe ./cmd/aidock
node web/tests/replica-state.cjs
node Demo/tests/regression.cjs
```

并发 race 构建曾遇到宿主机资源不足，改为限制构建并发；没有停止用户其他服务。最终结果以串行 race 和新改动的针对性复验为准。前端七组状态回归与 Demo 58 个替代 DOM/计时器用例通过；这些用例不等同于浏览器或外部工具验收。Linux/amd64 交叉构建仅证明可编译，不声称 Linux 运行验收。

内置浏览器验收使用五个独立样例项目：选择采用源、保留目标和跳过；取消保留决策；两个目标与共同基线共同应用、回退、撤销；新版与旧版记录重开；刷新/进程重新启动后历史保留；窄屏布局与控制台日志。原始五份技能源的 **51 个文件 SHA256 与 51 个目录**完整一致。

## 未通过的总门槛

下一步是一个外部生成器的暂存输出、源/镜像映射和恢复清单适配，以及源/生成物/真实共同基线的一起提交与恢复。继承、覆盖、分叉和外部权威源继续不能被静默压平为自有源；未通过的生成器仅诊断。

当前多目录事务在独立预演根验收，不是实际项目发布授权或真实生成器验收，也不是 OS 沙箱。实际工具新会话正文加载 L3、模型能力使用 L4、受管 MCP 和完整 1E 联合验收仍需补齐；阶段 1 以及完整 1C/1D/1E 均不勾作完成。
