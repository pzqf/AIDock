# AIDock 开发计划

> **本文只做计划，不含排期**（各阶段耗时由你按实际情况决定），也不含实现细节。
> 实现细节一律以 [设计文档](./AIDock-设计文档.md) **v0.19** 为准；本文只回答四件事：**按什么顺序做、每阶段做到什么算完、依赖什么、风险在哪**。两者冲突时以设计文档为准。

---

## 一、总原则

1. **骨架先行**：先把「项目空间 + 技能管理」跑通，其余能力都是往这个骨架上挂。
2. **安全与骨架同步建**，不做"先跑通再补安全"——安全门 / 进程隔离 / 凭据注入是不可替换的不变量（设计 §8.1），后补等于返工。设计 §14 已明确：安全**不是**独立阶段，而是第一阶段的底座。
3. **每阶段都要产出可独立使用的成果**，不允许出现"做很久还用不上"的阶段。
4. **CLI 是契约，界面是外壳**（设计 §10.0）：每个能力**先有 CLI，再有控制台入口**，且界面入口与 CLI 等价（同一条命令、不另起逻辑）。
5. **范围克制**：自研记忆引擎、远程访问模式、多记忆 MCP 的融合、团队功能等已明确列为**可选或不做**（设计 §13.2 / §9.4 / §7.5），**不在本计划内**。

---

## 二、阶段总览

| 阶段 | 名称 | 一句话目标 | 完成后你能做什么 |
| --- | --- | --- | --- |
| **0** | 工程脚手架 | 可编译、可测试、可运行的 CLI 空壳 | `aidock --help` 能用，CI 能跑测试 |
| **1** | 项目空间 + 技能管理（**含安全底座**） | 骨架立起来 | 在真实项目里启用技能，同步到 2 个 AI 工具 |
| **2** | 记忆能力集成 | 接上现成的记忆 MCP | 在项目里检索 / 写入记忆 |
| **3** | 全局技能库 + 插件市场 | 会装、会管 | 从市场装插件，项目继承全局技能 |
| **4** | 同步迁移 + MCP 网关 | 跨机、对外 | 换电脑一条命令恢复；AI 客户端可调 AIDock |
| **5** | 自动沉淀 + 多 AI 并行 | 收尾 | 会话自动摄取，多工具同时同步 |

> 阶段 **1–5 与设计 §14 的五个阶段一一对应**，新增的只有 **阶段 0**（设计文档里没有工程脚手架这一环）。

## 三、阶段 0：工程脚手架

**目标**：把工程地基铺好，后续每个阶段都能"写—测—发"。

**范围**
- Go module 初始化；仓库目录结构（`cmd/` `internal/` `web/` 等）。
- CLI 框架选型与骨架：`aidock --help`、子命令注册机制、退出码约定。
- **`--json` 输出约定落地**（设计 §7.7）：所有命令统一支持人类可读 + `--json` 两种输出。
- 数据根解析：`--home` / `AIDOCK_HOME` / 用户配置 / 默认路径的优先级链（设计 §7.8）。
- 测试骨架：单元测试 + golden 文件比对的基础设施（设计 §20.4 的快照测试要用）。
- CI：编译 + 测试 + lint。

**交付物**：一个**什么都没做但结构完整**的 `aidock` 二进制。

**验收标准**
- [ ] `aidock --help` 列出命令面，且**命令表与设计 §7.7 一致**（不允许多也不允许少）。
- [ ] `aidock version --json` 输出合法 JSON。
- [ ] 数据根优先级链有单元测试覆盖。
- [ ] CI 在干净环境能编译并跑通测试。

**前置依赖**：无。

**主要风险**：命令面在阶段 0 就定型，后续阶段加命令时要回填设计文档 §7.7——**别让代码和文档分叉**。

## 四、阶段 1：项目空间 + 技能管理（含安全底座）

**目标**：整个产品的地基。项目空间立住，个人沉淀才有地方放、多 AI 输出才有源头。

**范围**（设计 §7.1 / §7.3 / §7.4 / §9.1 / §9.2 / §9.6 / §19.2 / §19.3 / §19.6）
- `.aidock/` 项目目录结构与规范配置格式（`project.yaml` / `profile.yaml`）。
- Profile 与 **`全局默认 → extends 链 → 项目覆盖 → 临时会话`** 的合并算法（§19.6）——**必须确定性**，同输入必同输出。
- 技能三种作用域（全局 / 项目 / 继承）的管理与启用 / 禁用。
- 适配器机制：把配置**编译**成原生格式，同步到 **2 个 AI 工具**（Claude Code 优先 + 一个）。
- 编译报告 + 漂移检测（§7.2 / §8.3）。
- **安全底座（与上面同步建，不是后补）**：安全门（§9.1，含 L1–L4 信任等级）、进程隔离（§9.2）、凭据库与注入（§9.6）、审计日志（§9.5，追加写 + 哈希链）。

**交付物**：可用的 CLI + **最小控制台**（项目导航 + 项目详情页的「技能」「规则」「AI 工具」三个 tab）。

**验收标准**
- [ ] 在一个真实项目里 `aidock apply`，能把技能编译并写入 2 个 AI 工具的原生配置；工具侧实际生效。
- [ ] `.aidock/` 是唯一规范源；`apply` 只重写托管区块，**托管区块外的手写内容一字不动**。
- [ ] 合并算法有**表驱动用例**，且断言确定性（同输入必同输出、跨机一致）。
- [ ] **重新 apply 是幂等的**：不改配置连跑两次，第二次 diff 为空。
- [ ] 低于信任等级门槛 L2 的插件，安装时**必须显式放行且写审计**；放行记录可在 `aidock audit` 查到。
- [ ] 凭据**只落 OS 凭据库**——配置文件里 grep 不到明文。

**前置依赖**：阶段 0。

**主要风险**
- **合并算法是全局最难的一处**（四层叠加 + 链式解析 + 环检测）。若做得含糊，后续每加一种配置都要返工 → 建议**先写测试用例再写实现**。
- 适配器直接对接第三方工具的原生格式，**格式易变** → 适配器必须是**独立可更新单元**（§7.2），不能编译进 core。

## 五、阶段 2：记忆能力集成

**目标**：把记忆能力接上——注意 **AIDock core 不实现记忆引擎**（设计 §13.2）。

**范围**（设计 §7.5 / §9.3 / §13.2 / §19.4）
- 选定并接入**一个现成的记忆 MCP**（如 cgh），纳入 `mcp.yaml` 注册表。
- 记忆 MCP 的权限清单过安全门；写操作需授权 + 记审计。
- 按 §9.2 的模型隔离运行记忆 MCP。
- 检索作用域配置（默认本项目 + 跨项目知识 + 参考代码库，不串到别的项目）。
- 「待确认队列」：摄取内容**默认标 Internal**，可逐条调级；**Restricted 永不自**动摄取。

**交付物**：项目详情页「记忆」tab + 控制台「智库」视图。

**验收标准**
- [ ] 能在一个项目里通过 MCP 完成一次「存 → 检索」闭环，且**core 侧不产生任何记忆数据库文件**。
- [ ] 记忆 MCP 进程按声明的隔离等级运行；越界访问（越目录 / 越网络）**被拒且有审计**。
- [ ] 检索作用域生效：项目 A 的会话**检不到**项目 B 的记忆。
- [ ] 记忆 MCP 崩溃时**返回结构化错误**，不拖垮 core。

**前置依赖**：阶段 1（注册表、安全门、隔离、审计）。

**主要风险**：外部记忆 MCP 的接口/存储形态不由你控制 → **契约要稳**，别把某个 MCP 的特性写进 core。

## 六、阶段 3：全局技能库 + 插件市场

**目标**：从"手工装"升级到"会装、会管"。

**范围**（设计 §10.17 / §11.1 / §11.2 / §7.2 / §19.5）
- 全局技能库管理；项目可从全局继承或覆盖。
- 插件市场：聚合官方 Registry / npm / GitHub 搜索；**取数由 core 后端代理，浏览器不直连**（§10.17）。
- 缓存与离线降级：缓存于 Local Root，离线展示旧缓存并标注"可能过期"。
- 安装弹窗（§11.1）：三件事一眼读完 + 信任等级徽章 + 低于门槛的二次确认。
- 批量操作与一键更新（§11.2）：全部更新、更新角标、落地刷新不刷页。
- 安装路径统一：市场 / URL / 团队索引**都走同一套安全门**。

**交付物**：控制台「插件市场」+「插件详情页」+「技能库」。

**验收标准**
- [ ] 从市场搜到一个插件 → 看到信任等级 → 安装 → 同步到 AI 工具，全流程走得通。
- [ ] 断网时市场**展示缓存并标注过期**，不报错、不清空。
- [ ] 安装**事务化**：中途失败整体回滚，不留半成品（§20.1）。
- [ ] 一处安装入口被绕过安全门 → **视为缺陷**（不允许存在"快捷安装"）。

**前置依赖**：阶段 1（安全门、适配器）、阶段 2（若插件含记忆类）。

**主要风险**
- **取数协议与"评分"字段尚无定论**（§10.17 已标注属后续选型）：某些来源没有评分字段 → **取不到就隐藏该列，绝不用本地数据补造**。
- 市场的三方 API 会变 → 缓存与降级策略要早做。

## 七、阶段 4：同步迁移 + MCP 网关

**目标**：跨机器、对外暴露。

**范围**（设计 §7.6 / §7.7 / §7.9 / §19.10 / §20.2）
- Git 后端配置存储，**只同步 Capability 层**（密钥、会话、缓存、日志一律不随行）。
- `push` / `pull` / `bootstrap` / `export` / `diff` / `replay` 命令。
- **快照与回滚**：每次 `apply` 前自动快照；快照仓库由 core 在 Config Root **本地自建**——**因此即使同步档位选②（云盘目录、无 Git 远端），时间线与回滚依然可用**（§10.15）。
- 冲突处理：以 Git 冲突为准、**不自动合并**；有可视化则并排选边，**无则明确提示手工解决并阻塞自动应用**（§20.1）——绝不允许默默选一边。
- MCP 网关：**v1 只做 `stdio`**，把 `aidock` 注册为 MCP 服务器，**由 AI 客户端按需拉起**，core 不需要常驻。

**交付物**：CLI 同步命令 + 控制台「同步与迁移」+「时间线」。

**验收标准**
- [ ] 换机演练：新机 `bootstrap` 后环境恢复，且**密钥不随行**（需重新授权）。
- [ ] 任意历史快照可回放；回放**需二次确认**、走"快照 → 重新编译 → 原子替换"、**写审计**。
- [ ] 同步冲突时**不会静默丢改动**。
- [ ] MCP 网关以 stdio 形态被 AI 客户端拉起后，能列出插件 / 应用 Profile；**core 无任何常驻监听端口**。

**前置依赖**：阶段 1（配置规范、安全门）、阶段 2（记忆类工具不经网关）。

**主要风险**：`bootstrap` 是**用户最容易失去信任**的一步（换机、数据迁移）→ 必须可 dry-run、可回滚。

## 八、阶段 5：自动沉淀 + 多 AI 并行

**目标**：从"手动用"到"自动积累"。

**范围**（设计 §7.1 / §7.2 / §7.5）
- 会话自动摄取：**主动上报优先，被动扫描为辅且默认关**（§7.5）；产出**必须经"待确认"队列**。
- 多工具同时同步：同一套配置编译到多个 AI 工具，能力矩阵标注 `native` / `degraded` / `unsupported`。
- 项目类型自动识别 + **Profile 智能感知**（§7.1）：仅在明确不匹配时给**可忽略**的建议 chip。

**交付物**：自动摄取管线 + 多工具并行同步 + 智能 Profile 建议。

**验收标准**
- [ ] **不做"无授权自动读取全部对话"**：被动扫描默认关，开启后产出仍须人工确认。
- [ ] 一个工具不支持某能力时，**编译报告明确标注 `unsupported`**，不静默失败。
- [ ] Profile 建议**可忽略、可关闭**，忽略后不再重复打扰。

**前置依赖**：阶段 1–4 全部。

**主要风险**：被动扫描依赖各工具的**私有存储格式**（易碎）→ 会话源适配器同样要是**独立可更新单元**。

## 九、横切事项（贯穿所有阶段）

| 事项 | 要求 | 挂靠 |
| --- | --- | --- |
| **安全门** | 每次安装 / 依赖安装都走，不可绕过 | 阶段 0 起 |
| **审计日志** | 追加写 + 哈希链，**不可关闭、不可篡改** | 阶段 1 起 |
| **测试策略** | 适配器用快照测试；合并算法用表驱动；安全门用**负向用例**；隔离用越界用例 | 阶段 0 建基座 |
| **性能目标** | 只承诺 core 自己的：冷启动 < 2s、单次 apply < 3s。**索引 / 检索指标属记忆 MCP，core 不承诺** | 阶段 1 起 |
| **控制台** | 每加一个 CLI 能力，同步加等价的控制台入口；界面不得另起逻辑 | 阶段 1 起 |
| **文档同步** | 代码与设计文档分叉即视为缺陷；设计变更要回填文档 | 全程 |

## 十一、本计划明确不做的事（v1 边界）

以下**不是遗漏，是决定**：

- ❌ **自研记忆引擎**（CogniBox）——列为可选项，v1 复用现成记忆 MCP（§13.2）。
- ❌ **远程访问控制台**（`--remote` / 绑 0.0.0.0）——明确不做，需要跨机请走 SSH 隧道（§9.4）。
- ❌ **core 常驻服务**——控制台用完即退，MCP 网关走 stdio 由客户端拉起（§10.0 / §7.6）。
- ❌ **多记忆 MCP 的结果融合（RRF）**——若有需要，交给独立的聚合 MCP，core 只做注册与编排（§7.5）。
- ❌ **`curl | bash` 安装方式**——一律走带签名校验的 `aidock bootstrap`（§10.6）。
- ❌ **自动合并同步冲突**——以 Git 为准，交用户决定（§20.1）。
