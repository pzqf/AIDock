# 纯生成物修复与排除保护实施

开发版本：v0.16.0-dev。日期：2026-10-14。设计基线：v0.24。阶段：1D 子集。

## 行为

“仅预览生成物修复”独立于源差异处理。源一致、双方冲突尚未选边、目标有自己的改动时，都可以选择工具，按每个目标自己的已保存源检查输出。比较摘要只用于固定观察，不赋予采用发布者内容的权限；修复没有源决策，不修改源或推进共同基线。

可重新生成缺失的整个工具目录；已归属包与旧归属摘要一致时，可更新到该目标的新源版本。保留手写包，未归属同名占用、无效归属、未排除的人工漂移仍阻断。部分受管文件被删也按漂移处理，不能自动覆盖用户意图。

本机排除策略覆盖普通生成暂存与纯修复。排除按完整包生效；原生名称、源 UUID 及其子路径、skills 整体排除均支持。源 UUID 同时保护旧原生名称；排除旧原生名称时，也保护其已归属身份的新名称，防止同一 ID 生成两份归属。现有文件、二进制、空目录、模式和原归属记录保留；排除项不创建、不接管、不删除，也不以重算摘要承认人工修改。退役/停用不取消该保护。预览显示保护范围与未知证据。

生成目录已一致或全部技能被排除时，仍可查看逐项诊断，显示“无需修复”，禁止建立空预演事务。它不表示已验证会话生效。确认前源/目标/策略/基线/适配器观察变化均使计划过期。

## 契约

- CLI：`replica generation repair --file <JSON>`。
- JSON：`from`、`targets`、`comparison_digest`、`tools`；不接受源决策、任意目录或命令。
- API：`POST /api/replica/generation/repair`，同样要求会话、Host、Origin、CSRF 和严格字段检查。
- 确认：沿用 `replica rehearsal run-generated --plan <生成清单 UUID> --digest <完整摘要>`；源修复计划不能误走源预演入口。
- 清单：generation schema 2 新增 `repair_only`、`no_changes`、逐目标 `preserved`；所有新增可选字段对历史摘要为零贡献。
- 历史：schema 1 生成清单和旧预演记录继续可读/恢复。未包含排除保护的旧清单必须重新暂存，不能直接继续采用。

纯修复继续使用固定独立根的协调事务。技能源与基线虽没有候选变化，仍作为绑定观察和恢复范围，生成物可回退、撤销与中断恢复。原始登记项目仅观察；真实项目发布未开放。
