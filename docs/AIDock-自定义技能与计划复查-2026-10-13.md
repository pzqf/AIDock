# AIDock 自定义技能与开发计划复查

日期：2026-10-13。当前基线：**v0.24**。新增诉求：管理大量项目自定义技能，并复查开发顺序与验收门槛。本轮完成设计/计划修改，没有实现 Go CLI 或真实技能写入。

## 新增能力的首期边界

首期管理完整技能资产，不依赖联网市场。盘点只读取登记的源范围；已有生成器保持权威，镜像不重复当原源。同名服务端/客户端技能不跨 scope 合并，本机环境技能默认 copy-local。

创建/导入不执行脚本或安装依赖。需求/权限元数据用于审核与发布预检，外部 AI 客户端自行运行的命令不因此被 AIDock 隔离；受管执行仍走锁定 MCP/CLI 插件。未知来源/动态依赖/缺少工具版本证据显示具体缺口，不能给“已安全/已生效”总徽章。

源保存、原生 apply、replica 发布各有计划和恢复清单，不互相隐含执行。全局资产更新只产生新候选和引用影响；项目明确采纳精确版本。删除要解除 Profile/依赖/覆盖引用，离线未知引用只允许退役并保留包。回退源会产生待应用/待发布差异，不自动传播。

## 兼容与迁移

- `skills.yaml` 是新增独立 Schema v1；它保存稳定身份、来源、完整包及依赖，实际机器 Schema/golden 在阶段 0/1B 实现。
- `profile.yaml` 升为 Schema v2：skills 名称引用改为 UUID，并增加精确 revision 的 `skills.pins`。其它既有配置仍是其 Schema v1，不以设计版本号统一升级所有文件。
- 旧 Profile v1 仅兼容读取与迁移预览。按当前来源链确认 name→id/revision，唯一映射才可提出迁移；重名、缺失或旧隐式覆盖必须用户协调。写 v2 前保留旧文件/包，迁移失败恢复，不自动改外部原生格式。
- 覆盖保留同 id、基础来源与版本；独立分叉另建 id。实际导入五副本先确认映射/共同基线，不因为名称相同或内容一致就自动赋成同资产。
- revision 使用完整包原始字节和语义元数据；文本换行变化会产生新修订。本文档基线的 UTF-8/LF 哈希仅用于文档换行核对，不可替代运行技能包的原始字节摘要。

## 实施入口

建议下一项实施任务从**阶段 0 + 1A**开始：工程与 Schema/命令状态骨架、只读自定义技能清单、两个目标工具的发现/兼容证据，以及独立测试目录中的 Windows 隔离/适配可行性原型。然后做 1B 的源事务，再开放原生写入和五副本发布。

阶段 1B/1C/1D 的验收不能由本轮 Demo 回归替代。真实五工作区写入必须在后续实施任务明确范围后进行；当前仍只做设计。
