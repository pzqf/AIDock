# MCP 明确删除与副本恢复 · v0.86.0-dev

本增量补齐 MCP 删除意图在规范源、三方比较和完整同步中的传递。普通移除仍只改变当前源；缺失、损坏或暂不可读不代表删除。

## 使用流程

在 MCP 定义中移除原有条目后，可逐项勾选“同步明确删除”。默认不勾选。预览会同时列出 `mcp.yaml`、匹配的 `plugins.lock` 条目和 `mcp-removals.yaml`；确认后使用原有源事务保存，保留完整回退点。

跨副本比较把明确删除作为独立 MCP 定义组。每个目标分别选择采用源删除、保留目标或跳过。只有实际变化成员进入完整候选和共同事务；原比较名单仍保留用于重新核对。删除元数据的单独变化也不能绕过完整 MCP 发布门槛。

目标有共享、defaults、extends 或 Local 引用时继续阻断。共享 Profile 可以在同一处理方案中明确协调；Local 不会被默默清除。工具文件中的托管连接须经完整批次检查、预览和独立确认才会移除，手写条目保留。

## 数据与恢复边界

`mcp-removals.yaml` schema 1 仅保存原名称、定义 SHA256 和标准化精确锁 SHA256。不携带原配置正文、凭据、产物或授权。项目显式删除须绑定当前 copy，以便核对本机覆盖。安装记录、产物和授权历史保留，删除不等于卸载或撤销授权。

同名重新引入须确认当前删除记录摘要；清除该名称的删除记录，但不自动恢复旧锁、安装或授权。源回退和历史草稿投影保留删除记录原字节。完整批次成员回退、撤销与中断恢复沿用既有共同事务，不增加新的恢复权威。

源、锁或删除记录在预览后变化会使旧方案失效。严格确认从真实前后镜像重建允许的效果，拒绝重算摘要后夹带额外源文件、伪造删除、恢复无关锁或删除非本次移除名称。
