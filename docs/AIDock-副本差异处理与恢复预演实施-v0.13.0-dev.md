# 副本差异处理与恢复预演实施 v0.13.0-dev

日期：2026-10-14。继续阶段 1D，已完成逐项决策、完整候选与独立预演；正式跨项目发布仍关闭。

## 能力

- 三方比较后，每条差异必须明确采用源、保留目标或跳过。缺共同基线可以明确选边，不按时间猜测；本机排除与未支持的外部权威禁止采用源。
- 完整候选绑定当前比较摘要，保存源、全部目标、分支、本机排除和共同基线。构建前后重读核验，确认预演前再次核验。缺决策、重复/未知决策、错误摘要与过期计划均阻断。
- 独立 owned 项目技能可形成完整候选：包字节、二进制、空目录、元数据、Profile pin/启停、退役原因与时间一起处理。保留目标已有修订缓存、草稿和无关文件，不把发布者的本机 Origin 路径带入目标。物理移除没有完整恢复资产时不推定删除。
- 每个目标单独检查完整包、名称槽位、引用、依赖及平台。已启用集合的静态 FAIL 阻断候选；工具版本/执行权限/会话证据仍按原层级显示 UNKNOWN。
- 采用源后拟推进对应条目的共同基线；保留目标和跳过不改变发布者、不推进真实基线。候选只有预演确认入口，真实项目发布入口继续返回未实现。
- 独立预演复制所选目标的完整 `.aidock` 树与控制数据，使用现有持久批次写入器应用候选及预演基线。回退、撤销、恢复和历史使用相同记录；未恢复的预演阻断新预演。回退目标被外部编辑时拒绝覆盖。
- 页面保留取消后的选择，显示每个目标处理方式、候选变化与检查结果。预演记录可在进程/页面重启后读取；失败时刷新恢复状态。源副本在所有忙状态切换后仍不能被勾选为目标。

## 命令

与 v0.12 相同的 `--managed-root / --home / --project / --scope` 绑定下：

```text
replica compare --from <copy UUID> --to <copy UUID,...>
replica resolve --file <决策 JSON>
replica rehearsal run --plan <候选 UUID> --digest <完整摘要>
replica rehearsal latest
replica rehearsal plan --session <预演 UUID> --transaction <最新成功事务 UUID>
replica rehearsal apply --session <预演 UUID> --plan <回退 UUID> --digest <完整摘要>
replica rehearsal recover --session <预演 UUID>
```

决策 JSON 使用 `from`、`targets`、`comparison_digest` 与 `decisions`。每项决策包含 `target`、`entry` 稳定 UUID 和 `choice: source | target | skip`。CLI/API 均拒绝未知字段和多个 JSON 对象。`replica confirm` 仍只确认登记/首次共同基线，不能用来执行候选或回退。

启动五副本专用项目使用 `scripts/start-replica-demo.ps1`。初始化中断残留目录不会被重置；重复启动保持原始副本和预演历史。新候选及预演记录放在显式 home 的 `local/replica-resolutions/`，不自动清除恢复点。

## 探针进程修复

整仓实际工具集成曾发现：Claude 初始化发现 PASS，但其子进程占用临时目录，使 Windows 清理失败。现在 Windows 在挂起状态启动探针，加入专属 Job 后恢复主线程；成功、取消及超时都回收该 Job 中的进程，确认退出后释放资源。Unix 使用专属进程组回收。

Windows 父子进程夹具同时覆盖正常结束和取消，退出后目录可改名；真实 Claude Code 2.1.257 与 Codex CLI 0.162.1 发现、检查后安装及回退集成复验通过。此次修复只证明探针进程生命周期，不证明 AppContainer、ACL、网络隔离或插件沙箱。
