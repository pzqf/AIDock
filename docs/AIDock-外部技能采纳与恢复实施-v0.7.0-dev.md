# 外部技能采纳与恢复实施 v0.7.0-dev

日期：2026-10-13。设计基线保持 v0.24，本次交付阶段 1B/1D 的外部候选采纳与批准缓存子集，不代表阶段 1 已完成。

## 已实现

- 外部完整包显式采纳：同时绑定 bridge、project、scope、copy、绝对原源根、包相对路径、精确包 revision、集合 revision 和登记文件字节摘要。预览后任一绑定或候选变化阻断提交。
- 原源只读：包不会进入可编辑的 `skills/<id>`，外部包独立进入有效集合；查看正文/二进制、选择历史版本、本层开关与引用检查可用，编辑、治理改写、改名、退役、覆盖和分叉保持阻断。
- 包缓存、批准记录、项目选择及 Profile pin 在同一可恢复事务中提交。保留普通字节、二进制附件、空目录与当前平台模式；失败自动恢复，中断后先恢复再允许新保存。
- 外部包采用 `external-package-v1`，直接沿用桥接的完整包候选 digest，包含标准化可执行位。只改变可执行位也产生不同缓存路径，不能覆盖旧批准包。相同候选 revision 的再次批准只新建批准记录，复用首次完整缓存，不因原源非可执行权限变化改写旧缓存。owned 的 `semantic-v1` 算法保持原约定。
- 外部包首次采纳分配稳定资产 UUID，初始停用。后续候选采纳沿用 ID 与本层开关；回退到首次采纳前后再次采纳，也从保留的批准记录恢复原 ID。
- 离线选择已批准版本：原源目录或登记文件消失时仍可读取缓存，并显式预览选择历史批准包。选择只改变当前项目 pin；不还原外部目录。
- 源回退保留不可变批准历史和包缓存；撤销回退恢复回退前的选择与已保存草稿。首次初始化前的空项目根仍不能作为历史恢复点，初始化失败则由事务自动恢复。
- 项目基线检查：`project_pins` 单独报告已采纳包与当前候选的差异，包含缓存可用性。外部登记被移除、原源身份改变、扫描清单移出已批准包、源漂移/消失均有具体结果。登记文件的集合基线与项目包级批准分别展示。
- 写入根保护：项目根与 Local Root 不得重叠任何外部登记根；已有批准历史也阻止另一个 `--home` 将备份写入外部目录。缓存的字节/摘要、清单、pin、来源记录或身份不符会阻断使用。

## 磁盘结构与权限边界

项目 `.aidock/` 新增 `external-skills.yaml`（当前选择）和 `.external-approvals/<skill-id>/<approval-id>.json`（批准历史）。完整包在 `.revisions/<skill-id>/<package-revision>/`，原字节备份及事务日志仍放在显式 home 的 Local Root。

批准记录保存来源身份、扫描选择、集合/包 revision、时间及完整技能清单。批准身份用于明确选择和防止原源重新定位；生成器声明只是身份记录，不表示执行能力已验证。批准缓存是逻辑只读、摘要可校验的版本材料，不声称能抵御同用户同时改写全部本地记录。没有自动清理历史的功能。

外部登记文件不由采纳动作写回；登记中的可选 `approved_revision` 继续作为手工提供的集合比较基线。真正的包级采纳选择位于项目事务中。当前不要求把整个集合一口气采纳，也不能把采纳一个包等同于批准整个源集合。

外部包的原生 frontmatter 与文件原样保留，本阶段没有外部治理声明格式转换；额外执行/依赖声明不能通过 AIDock 编辑。实际工具发现、会话加载、脚本执行、OS 隔离以及生成器暂存/恢复能力仍为未验证或未开放。

## CLI 与控制台

外部采纳需要原有项目源绑定，额外明确 `--bridge-file` 与 `--copy`。项目父目录须预先存在；开发测试只使用专用夹具项目。

```powershell
.\aidock.exe config --managed-root <测试项目/.aidock> --home <隔离数据根> --project <UUID> --scope server --copy isolated-test --bridge-file <bridge.yaml>
.\aidock.exe skill plan external-adopt --file <adopt.yaml> <同一组绑定参数> --json
.\aidock.exe skill apply --plan <plan-id> --expected-digest <预览摘要> <同一组绑定参数> --json
.\aidock.exe skill plan external-select --file <select.yaml> <同一组项目绑定参数及--copy> --json
```

`adopt.yaml` 必须使用检查结果中的精确值：

```yaml
bridge_id: 33333333-3333-4333-8333-333333333333
package_path: skills/guide
revision: sha256:<包摘要>
bridge_revision: sha256:<源集合摘要>
```

`package_path` 相对登记的外部根，不能按动作描述文件目录重新解析。历史选择描述只接受 `id: <技能UUID>` 与 `approval: <批准UUID>`。它读取项目缓存，不需要当前登记文件存在，也不会重新扫描/下载原源。

控制台“外部源检查”提供候选采纳入口；“已批准的外部技能”提供历史版本选择；“保存记录与回退”沿用源回退和撤销入口。CLI、HTTP 与页面调用同一个 Manager，认证、CSRF、未完成事务和草稿保护沿用现有控制台。

## 验证与限制

Windows 验证包括完整包/二进制/空目录、离线读取/选择、回退/撤销、ID 稳定性、错误副本/作用域、登记及源变化、重名、缓存损坏、写入根重叠、第二项失败和中断恢复，以及 CLI/HTTP 契约与 CSRF。全仓 race 测试、vet、Windows 构建和 Node 回归通过。Linux/amd64 程序及 source/bridge 测试可交叉编译；本机未执行 Linux 测试，可执行位改变的独立测试只在 Unix CI 执行。

Codex 内置浏览器使用 `.artifacts/external-approval-final/` 验收：首次采纳初始停用、候选与项目基线一致仍保留生成器 UNKNOWN、附件变化的包级 drift、过期预览阻断、更新后两份批准保留、源消失时 FAIL 且缓存可用、离线选择旧包、二进制摘要、撤销选择及控制台刷新/关闭。页面状态回归为 48 项，原只读状态 5 项和 Demo 58 项保持通过；Demo 仍是内存模拟。

外部源不受 AIDock 的写入锁控制。提交前重查阻断已观察到的变化，事务提交的是预览固定的完整包；原源若在提交检查后并发变化，后续检查报告 drift，不承诺跨两个权威目录的原子观察。

`E:/work`、`E:/work2`、`E:/work3`、`E:/work4`、`E:/work5` 本轮未读取或修改，不能作为测试目录。原生工具应用、生成器写回、跨副本发布、批次恢复与 OS 隔离尚未开放；已批准包的回退只改变本项目版本选择。
