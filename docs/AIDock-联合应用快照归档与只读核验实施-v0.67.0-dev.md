# 联合应用快照归档与只读核验 · v0.67.0-dev

Profile 联合应用现在先在受限 Local 中归档当前绑定项目的完整规范源、已展开配置和全部有效技能包正文，再按原门槛提交目标。时间线可查看元数据、核验归档字节。完整项目 replay 写入尚未开放，本增量为其补齐独立保存的材料；原组件回退和正式副本恢复继续保留。

## 使用

需要本机 Git 和明确稳定的 copy UUID；已登记项目自动提供绑定。准备阶段缺少这些条件会保留预览并阻断确认。默认 AI 工具联合安装会先保存归档；静态预览、准备和取消不创建应用快照，零变化仍拒绝重复安装。新增入口：

```text
aidock snapshot list <绑定参数> --json
aidock snapshot check <snapshot-id> <绑定参数> --json
GET /api/snapshots
POST /api/snapshots/check  {"snapshot_id":"<UUID>"}
```

管理界面：时间线与回退 → 联合应用快照 → 读取应用快照 / 核验归档完整性。只返回摘要、版本、计数、身份和原事务状态，不返回配置值、规则/技能正文、原生备份正文或任意 Git 命令执行入口。GET 使用当前绑定，POST 严格校验字段、重复键、类型和 CSRF。列表不自动声称正文完整；显式 check 只验证本归档字节，不验证当前安全策略、运行时依赖或前序引用。

## 保存范围与一致性

每个 project/scope/copy/source-root/native-root 有独立受限本机 bare Git 仓库，不关联或改动用户项目 Git，不配置远端。清单及去重 SHA256 源正文对象保留项目 .aidock 全树、展开的有效配置和有效包的全部附件/二进制/空目录。实际包正文从已核对不可变缓存读取，不能只引用当前全局库；原缓存删除后仍可读取归档。

原生目标原/新字节只复制到同一归档边界下的 native-private 存储，不进入 Git。源与目标清单保留摘要、权限模式、精确事务和适配器版本；plugins.lock 等项目源随源树保存，运行时产物与外部服务本身不复制进 Git。全局库和本机配置层的原件管理、依赖可用性及恢复适配仍需继续实现，不能把归档完整性当成这些条件的验收。

源观察在现有源锁内核对。Git 归档在最终权限/目标锁段之前完成，之后仍执行原联合应用的完整复核，包括源、产物、授权、工具和 AIDock 程序、检查时效及实际目标。快照生成失败会阻断目标写入。最终复核失败留下的归档不是成功应用证明。

事务状态依赖原批次记录，核对完整原事务正文及摘要。找到 committed 只表示当次成功，回退以后仍是历史；prepared/recovered 分别显示待恢复/已恢复。未找到原记录一律 UNKNOWN，不能从缺失推断从未提交。仅在原记录成功且全部事务前目标与历史快照的 after 字节一致时保留 previous_applied 候选引用；缺失则明确未知，前序正文仍需独立核验。

归档清单严格拒绝重复键、未知字段及身份/摘要不一致。Git 使用固定本机参数、独立环境和空模板/钩子目录，不继承用户配置、凭据辅助器、trace、对象库路径或 Git 环境变量。拒绝仓库配置变化、链接、alternates、其它工作树和非空钩子目录。Windows fast-import 使用私有仓库内相对 Git 路径，避开长绝对 GIT_DIR 的限制。普通 API 错误不回显 Git stderr。这里只提供本机完整性与访问边界，不宣称外部可信锚点或能抵御可重写全部 Local 的攻击者。
