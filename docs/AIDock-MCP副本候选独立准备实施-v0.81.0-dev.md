# MCP 副本候选独立准备 · v0.81.0-dev

更新：2026-10-17。Goal active，阶段 1 与 59 条完整验收状态不提升。

## 可用流程

跨副本比较新增 `mcp-definition/<登记名>` 独立组，携带明确的 stdio 定义与精确版本锁。字段合同改变时，可在同一候选中明确采用对应 MCP 定义及已声明共享字段，服务端仍重新校验未来字段合同。源端缺失不视为删除；缺少锁、不可携带或未核验的定义不能传播。

目标保留自己的匹配产物路径；版本不同则分配独立版本目录，避免新包嵌套在旧包中使旧摘要失效。定义和锁不携带包字节、安装登记、来源/评估证据、授权、凭据或运行历史。文件权限只允许原始 `${PROJECT}` 路径，网络/来源中已识别的本机路径、回环地址或凭据特征阻断整组。这不是通用秘密检测器。

在页面逐项选边后点击「准备各目标 MCP」，依次完成目标自己的完整 ZIP 导入、安装登记、未来配置授权和固定 Node 运行时版本核验。已完成步骤默认折叠，下一项待办展开。支持预览、取消保留输入、明确风险确认、错摘要/重复确认拒绝、读取失败清空旧结果和迟到响应丢弃。

确认未来版本安装会替换此目标的同名安装登记，使原安装/授权不再匹配；旧包保留，安装历史可按当前依赖重新审查回退。确认未来授权同样会替换同名旧授权。准备状态只针对候选，不会自动应用源、工具文件或正式同步。未配置 MCP 的项目返回空准备集合。

## 契约与门槛

```text
aidock replica candidate show --file <JSON> <绑定参数> --json
aidock replica candidate artifact-plan|artifact-confirm --file <JSON> ...
aidock replica candidate install-plan|install-confirm --file <JSON> ...
aidock replica candidate permission-plan|permission-confirm --file <JSON> ...
aidock replica candidate runtime-check --file <JSON> ...
```

对应 API 全部为 POST：`/api/replica/candidate/<上述动作>`。CLI/API 共用副本管理器和既有产物、安装、授权及审计事务。

读取请求为 `plan_id/digest/copy_id`，必须属于已保存候选的明确目标。预览另含 `edit`；版本检查另含 `check`。确认另含 `name/operation_plan_id/operation_digest`，候选摘要和动作摘要分别核对。拒绝任意树、根目录、命令、重复键、别名、null、未知字段与错误类型；解析错误不反显输入值。

目标未来配置保持自己的全局库、extends 和 Local 覆盖，不把有效值压平到共享源。源、本机层、全局库或登记/共同基线改变均使候选过期。完整包、安装和授权属于实时检查门槛，正常准备不能把候选自身误判为过期；源与非 MCP 静态检查仍绑定，后续完整生成必须重新执行全部实时检查。

授权和运行时记录使用原本机权威，候选计划以候选摘要分域，当前源入口不能消费它。候选授权不使不同的当前源配置获得权限。固定版本核验只执行已独立授权的锁定 Node 版本命令，不启动插件；配置真实投影后的 MCP 进程匹配另有源码测试。

## 验证

证据目录：`.artifacts/experience-replica-mcp-candidates-v081/`。

- source 测试覆盖目标配置层、全局库变化、未来精确配置授权、实际 Node 版本与 MCP 进程匹配、跨入口确认拒绝，以及新版本 ZIP/旧包保留、安装替换、风险门槛、外改和占用目录拒绝。
- replica 测试覆盖启用 MCP 缺包时先构建源候选、导入及安装后候选继续有效、错误/未选目标拒绝、原源/基线不写入和发布者变化过期。重算摘要不能篡改未选择字节的既有回归保留。
- CLI/API 拒绝含糊输入并保持身份和方法认证；专用五副本的八项真实验收包括 ZIP 预览与确认、目标安装风险、未来授权、固定 Node 核验、三目标零授权传播、五棵项目树与旧包原字节保护、外改注入恢复。
- 内置浏览器验证逐项选择、待办展开、安装预览/取消/确认、单独授权、固定版本核验、两目标切换与 390/1280 宽布局。完成后通过原安装历史恢复第三副本旧版本并撤销测试授权，保留全部追加审计；源及工具完整树不变。
- 六包完整竞态通过。最终候选源门槛调整另有定向竞态和完整 source 回归；最终前端语法/状态、vet、Windows/Linux 构建结果以 `verification.json` 为准，Linux 仅构建未运行。

开发时修正了新入口空 MCP 集合被误报为缺锁，以及候选自身导入改变实时检查后被误报为过期的问题。一个跨运行环境对象比较断言改为规范 JSON 比较；浏览器的一次短等待早于异步授权读取完成，重读确认成功，未重复提交。新增发布门槛测试最初未先准备候选完整包，修正为按正常流程导包后再检查。

## 剩余

本增量完成未来配置的独立准备入口。**完整 Profile/MCP 当地联合编译、固定已应用视图、正式批次发布、源/原生文件/基线共同恢复，以及 MCP 明确删除墓碑仍未完成。** 未提供未来包的一键清理；未引用包保留，不能把缺失锁或未知文件当成可删除内容。来源/评估证据仍由目标自己登记，未开放第三方执行或复制源机器安全结论。

只要候选实际改变 `mcp.yaml` 或 `plugins.lock`，现有仅技能与规则的正式发布路径返回 `PUBLICATION_MCP_CONFIGURATION_REQUIRED`；预检报告及界面同样显示尚未开放，不能依靠重新选择生成范围发布不完整方案。判断绑定实际前后字节，不只信任界面决策名称。

下一增量把此候选接入原生编译和真实整批协调器，发布前保留私有快照与现有权限、工具发现和规则来源门槛。不能安装会跟随后来草稿变化的临时 MCP 参数，也不能用伪造的单目标 committed 记录代替全批提交证据。其它插件类型、外部生成器、真实技能 L3/L4、Windows 网络隔离/broker、依赖恢复、审计分段及阶段 2–5 继续按原计划推进。
