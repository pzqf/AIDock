## 当前行为

跨副本比较除完整技能包、元数据、独立开关及退役记录外，现在包含两个共享配置组。每组展示源、目标、共同基线、变化字段和明确的采用源/保留目标/跳过决策。缺基线不按时间推断，双方独立修改显示冲突。保留目标与跳过不会反向修改发布者，也不会推进该组基线。

| 配置组 | 字段所有权 | 采用源的含义 |
| --- | --- | --- |
| `profile/shared` | `profile.yaml` 的 name、description、extends、plugins、mcp | 只替换这些字段，包括源明确移除的可选字段；技能决策和其他字段保留 |
| `rules/shared` | `profile.yaml` 的 rules、rules_override；`rules/index.yaml` 登记的有序规则和正文 | 同步完整组内的正文、名称、UUID、顺序、启停、增加与删除；保留未登记文件 |
| 技能条目 | 完整包、元数据、共享 enable/disable/pin、退役 | 继续独立按技能决策，不因采用共享 Profile 改变目标的保留/跳过选择 |

配置组是明确的覆盖单位，不在组内自动合并。规则文件以 UUID 识别，精确保留正文的 BOM、CRLF 和空行。新规则与目标未登记同名文件冲突时阻断，不接管或覆盖它；停用规则也校验和传播正文。规则目录下任一排除路径保护完整有序规则组，防止产生未经确认的部分顺序。`profile.yaml` 排除同时保护技能决策，因为技能开关和 pin 也需要写此文件。

开放的 `config_overrides` / `config_remove` 还没有可携带字段所有权合同，不传播其值，在比较中只列出排除原因；目标原值保留。本机覆盖、全局库的本机路径绑定、未登记规则文件、草稿和原生手写内容不随发布者传播。

## 候选、基线与恢复

所有技能与配置选择先构建目标完整候选，再执行目标自己的分层合并和静态校验。选择仅改变规则或 Profile 时，不重写无关技能索引。共享修改与各目标自己的全局默认、继承引用、本机覆盖共同进入原生编译，不能把发布者的最终有效结果直接复制给目标。

共同基线仍为 v1，新增可选 configurations；无此字段的历史基线可读，新配置差异显示缺基线。初始化只补两端一致且缺失的配置组，不接受同时存在的技能冲突，也不推进已有配置基线。采用源后只推进实际采用的条目或配置组；新基线只进入独立预演的 Control 候选。

新 Resolution 为 v2，暂存、检查或预演前按当前观察及显式决策重新构建完整源和基线，核对绑定、Before/After、变化及静态报告。手改候选或基线后重新计算记录摘要仍被拒绝。旧 v1 记录保留可读，但不能携带新共享配置决策。历史比较结构变化后的旧活动计划需重新比较；已完成预演仍可打开、回退、撤销。

完整候选沿用目录/单文件共同事务：技能源（含 Profile/规则库）、共同基线、Claude Code/Codex CLI 技能目录和规则文件在独立测试项目中一起应用、恢复、回退和撤销。CLI、控制台 API 和管理界面复用同一后端。正式副本发布继续关闭。
