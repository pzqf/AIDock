## 使用流程

在「跨副本」明确协调共享内容，为每个目标独立准备精确包、安装、授权、运行时和全部接收工具的完整检查。汇总保存完整批次后，重读提案并单独确认同步。技能、规则、已适配的启用 MCP、目标规范源和对应基线进入同一个真实事务；发布者只读，目标当前本机覆盖保留。历史记录按真实共同日志显示，不能把历史检查当成当前通过。

「完整配置批次」可重开已保存批次、检查中断恢复，或选择恢复节点及明确成员。成员默认均未选中；预览、取消、重新核对和最终确认分别进行。界面分别显示原目标名单、明确选择成员及事务有文件变化的成员；选择数量不能用变化数量代替，旧记录缺少独立选择时明确显示未知。

若原应用的安装或权限已变化，旧参数继续被拒绝。恢复弹窗按原应用的精确合同提供独立 ZIP 导入、安装登记、新授权和固定运行时核验；各项都有自己的预览与确认。静态检查不会自动运行工具发现，也不能解锁恢复；只有全部原应用的完整工具发现检查通过，才可生成新的共同恢复提案，最后再次确认。后续保存的草稿与原固定应用分别保留，不通过回放旧权限来恢复执行资格。

当前支持已适配技能、规则和固定 Public 合同的 Node MCP；不代表其它插件类型、外部生成器、任意 Profile 字段或完整依赖恢复已经实现。文件提交和隔离发现不代表实际技能新会话 L3/L4 通过。

## CLI/API 契约

所有命令追加当前项目、作用域、发起副本及 home 的明确绑定参数和 `--json`。CLI 与认证控制台 API 共用同一严格请求解析和领域操作。

| 操作 | CLI `replica publication` 子命令 | 请求要点 |
| --- | --- | --- |
| 完整同步 | `full-apply` | `publication_id`、完整 `digest` |
| 真实状态 | `full-execution` | `publication_id` |
| 中断检查 / 恢复 | `full-inspect-recovery` / `full-recover` | `publication_id`，仅原批次绑定 |
| 选择恢复预览 | `full-restore-plan` | `publication_id`、`transaction`、非空且不重复的 `copies` |
| 恢复重读 / 确认 | `full-restore-show` / `full-restore-confirm` | `publication_id`、`plan_id`、完整 `digest` |
| 原应用审查 | `full-restore-review` | 上述恢复身份，再加 `copy_id`、`applied_binding` |
| 原合同独立准备 | `full-restore-artifact-*`、`full-restore-install-*`、`full-restore-permission-*` | 原应用身份、`candidate_digest`；`plan` 接受限定输入，`confirm` 接受原计划 UUID/摘要及名称 |
| 固定版本核验 | `full-restore-runtime-check` | 原应用/候选身份，精确核验摘要与明确 `probe` |
| 完整检查 / 重读 | `full-restore-prepare` / `full-restore-prepared` | 原应用/候选身份；完整工具集，发现与规则核验分别明确；重读使用原检查 UUID |
| 生成新参数 | `full-restore-regenerate` | 原恢复身份，逐副本、逐原应用的完整检查 UUID/摘要 |

API 为 `POST /api/replica/publication/<子命令>`；沿用本机会话、Origin、CSRF 和工作锁。原 `full-history` 仍为 GET。写入/准备请求通过 `--file` 传入，完整同步也支持 `--publication` 与 `--digest`；状态和中断检查/恢复可直接使用 `--publication`。命令帮助给出实际恢复命令。

拒绝未知字段、重复键、别名、null、缺少确认、扩大或缩小原检查范围、任意文件根、客户端源/原生正文、伪造事务或命令。新授权及安装确认额外绑定原共同恢复节点、原应用候选和操作种类，同内容的另一恢复提案不能替代确认。低于 L2 的安装风险、未隔离运行时和凭据引用仍须分别明确；本轮浏览器夹具无凭据。

## 保存、恢复和保护

完整批次使用真实共同日志及完整根锁，原生视图和快照引用实际提交。不会伪造独立成员成功记录。应用前和提交前再次核对提案、只读发布者、源/本机层、当前权限、安装、产物、固定运行时、工具及原生观察；重复确认已消费提案会被拒绝。

恢复只处理明确成员的原事务变化及对应共同基线。当前本机覆盖、不可变版本/治理历史、发布者和未选副本保留。重新生成只重建受管 MCP 字段和归属文件，不改原恢复的前镜像、范围、技能/规则或无关原生文件。共同恢复预览将后续草稿、Local 和原生兄弟文件的已捕获备份保留到共同私有缓存；不重新读取实时文件当作原件，也不把原生正文写进技能源缓存。

中断检查不依赖旧检查文件仍存在或旧执行权限仍有效；仍核验原绑定和恢复材料。额外修改导致冲突，保留现场并拒绝覆盖。仅清理标记和文件恢复状态分别显示。完整批次引用会阻止移除发布者、目标或发起入口，归档保留引用。

恢复节点不是任意历史时间点：原完整应用节点和最新成功回退/撤销节点有不同语义。重新生成启动参数后，较老节点的旧镜像可能与当前受管文件冲突；此时可从最新成功事务撤销，不能绕过冲突门槛或覆盖当前文件。多视图同名安装合同冲突、明确删除墓碑及更完整的历史依赖协调继续列为后续工作。
