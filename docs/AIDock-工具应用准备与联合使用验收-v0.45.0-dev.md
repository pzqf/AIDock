# 工具应用准备与联合使用验收

版本：v0.45.0-dev。状态：主流程已实现并经专用项目验收；阶段 1 和整体 Goal 继续。

## 用户流程

AI 工具页以“准备工具应用 → 核对并安装 → 应用记录与回退”为主路径。明确所选工具和本地检查范围后，一次核对源与目标、隔离技能发现及规则来源，再生成同一输入的文件安装预览。检查不会安装文件；取消确认不发起检查或写入。安装仍须独立预览确认，并自动留存联合恢复点。

准备结果直接显示源与目标、工具发现、规则来源、文件预览四项状态。通过的详细证据默认收起；失败与未验证条件展开显示具体原因。外部生成器和 OS 隔离原型移到主流程之后，保留原有入口与边界。无文件变化时显示已一致并禁用重复安装；仍可查记录和回退。

## CLI / API

- aidock tool prepare --all：默认静态核对，不启动工具进程，不授予安装资格。
- aidock tool prepare --all --probe --rule-probe：显式在空配置独立临时项目检查两工具，包含已登记规则的加载来源。可用 --tool 限定工具、--rules-file 保留明确的逐工具冲突决策。
- 返回 check、plan、gates 和 status；READY 仅代表可独立确认原生文件安装，NEEDS_CHECK / NEEDS_ATTENTION 说明待验证条件，BLOCKED 说明源或目标冲突。CLI 未完成条件退出 3，静态阻断退出 5。
- POST /api/native/prepare 使用与既有 check 相同的严格请求字段、项目会话绑定、鉴权、CSRF、串行任务锁及方法检查。HTTP 请求成功与准备结果是否可安装分别表达。
- 查看变化沿用 aidock diff --plan <UUID> --expected-digest <digest>；安装沿用 aidock apply；回退与撤销继续使用工具事务合同。

上述命令沿用现有项目绑定参数或 --binding，不接收调用方指定的工具程序、版本、任意目标目录或预置成功证据。

## 保护与证据边界

复用现有 Check、compile 与 qualify；不会建立第二套较宽松的安装判定。检查后的源、配置或目标变化会拒绝准备；二进制身份、精确版本、规则来源和语义条件仍由原资格判定核对。可诊断的未完成条件保留未授权文件预览；记录损坏、过期或输入变化等错误直接返回，不伪装成成功。

前端取消、重复点击、迟到响应、工具选择变化、源变化和未恢复事务均有保护。已明确的规则覆盖决定带入同一检查与计划；不自动选择覆盖。准备与安装只使用已保存版本，保留页面草稿。

L1 文件一致、L2 隔离发现和独立规则来源分别显示。READY 不提升实际项目 L3/L4，不启动 MCP，不执行技能脚本，不发送模型提示，不引入用户配置或凭据。原生客户端后续执行技能仍属于 external。
